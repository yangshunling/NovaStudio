## ✨ 为什么是 Nova Studio

大部分 AI 工具只解决“聊天”这一件事。Nova Studio 想解决的是：

> **当你有多个 Agent、多个项目、多个角色时，如何把它们组织成一条真正能跑起来的生产线。**

- **不用在多个 CLI 之间来回切换** —— 一个窗口接入 Pi、OpenCode、Claude Code、Codex；
- **不用每次重新写提示词** —— 把角色、模型、MCP、技能、知识库固化成“数字员工”；
- **不用靠人肉传递上下文** —— 把员工串成工作流，节点产物自动交给下一个节点；
- **不用把资料散落在各处** —— 把 Markdown 文档收进知识库，员工按需读取并引用；
- **不用猜它跑到哪一步** —— 在画布上直接调试，节点状态实时可见；
- **数据完全在本地** —— 对话、员工、工作流、知识库与运行产物都由你自己保管。

## 🚀 核心功能

### 1. 多 Agent 对话工作台

- 自动扫描本机已安装的 Agent CLI，一个窗口统一使用；
- 流式渲染 **思考过程 / 工具调用 / 正文**，工具调用带分类图标与目标摘要；
- 多轮对话复用 CLI 自带 session，完整继承该 Agent 的工具生态；
- 支持 Markdown、GFM 表格、代码高亮；
- 完整事件流落库，重启后仍可回放含思考与工具调用的历史对话；
- 多会话可同时运行，互不阻塞；
- 输入框支持 `@` 提及项目文件。

### 2. 项目与工作区

- 以“文件夹 + 名称”为项目，所有会话共享同一个工作目录；
- 「新建会话」页左侧以「项目 → 会话」树组织，支持折叠、重命名、删除、清空会话；
- 项目同时作为工作流的工作区：运行目录、产物目录都由它决定；
- 可创建多个工作区；不同工作区的运行产物按工作流 ID 与运行 ID 分目录存放，互不覆盖。

### 3. 数字员工

把一份 Agent 运行配置固化成可复用的“员工”：

- 头像、姓名、职位、简介；
- 绑定 Agent 后端与模型；
- 独立的系统提示词 / 人设；
- 从 MCP 库勾选服务（服务定义统一在「MCP」页管理，员工只保存引用）；
- 从技能库勾选技能（技能内容统一在「Skill」页管理，员工只保存引用）；
- 从知识库勾选 Markdown 资料（内容统一在「知识库」页管理，运行时作为员工能力的一部分注入）；
- 员工卡片直接展示已启用的 MCP、技能与知识库数量；
- 一键启用 / 停用员工；
- 工作流节点直接引用员工，无需重复填写角色信息。

常见的员工角色示例：需求产品工程师、业务架构师、程序员、测试工程师、代码评审员。

### 4. 工作流编排与调试

**可视化编排**

- 工作区 → 工作流两级管理；
- 画布支持拖拽节点、缩放、平移、自动布局；
- 节点类型：开始、结束、数字员工节点；
- 从节点右侧端口拖出连线，选中连线后可删除或改连目标；
- 点击左侧数字员工即可快速加入节点；
- 运行记录、重命名、复制、删除都在工作流卡片上完成，工作流列表支持搜索。

**节点配置**

- 绑定数字员工；
- 任务详情（下发给该员工的完整指令）；
- 失败策略：失败停止 / 自动跳过 / 自动重试（可配置重试次数）；
- 审核门禁：自动通过 / 人工审核；
- 人工审核在执行前暂停，通过后才启动 Agent，驳回按失败策略处理。

**画布内调试**

- 点「调试」不跳页，直接在当前工作流里运行；
- 节点实时显示执行中、等待审核、成功、失败、跳过、取消；
- 顶部调试栏展示进度、当前节点、耗时、错误信息；
- 等待审核时可直接通过 / 驳回，并查看任务详情；
- 可随时终止本次调试。

**运行记录与产物**

- 每次执行都有独立记录：状态、开始时间、完成时间、总耗时；
- 点击详情可查看每个节点：
  - 提交给 Agent 的系统提示词与完整输入；
  - Agent 的返回内容；
  - 结构化交接单；
  - 本次注入的知识库与文件清单；
  - 运行参数与隔离环境告警；
  - 产物文件列表，可一键打开目录；
- 每个节点独立会话、独立运行环境；Claude 节点使用 Nova 自管的连接配置，每次尝试都创建全新的隔离配置目录（不继承本机 `~/.claude`），MCP 与技能按员工隔离；
- 产物落在工作区 `.novastudio/` 下，按工作流 ID 与运行 ID 分目录，互不覆盖；
- 工作流会话不会出现在普通项目会话列表中，避免干扰日常聊天。

### 5. 技能资产

- **一个可写主库 + 两个只读来源**：
  - Nova 技能库 `~/.novastudio/skills/`：可导入、编辑、删除；
  - Claude 全局 `~/.claude/skills/`：自动扫描，只读引用；
  - 共享技能库 `~/.agents/skills/`：自动扫描，只读引用。
- 支持导入技能目录（可批量导入子目录，兼容 `SKILL.md.txt` 这类隐藏扩展名文件）；导入即快照，源目录后续变化不影响已入库版本；
- 自动校验 frontmatter（`name` / `description`）、统计文件数与脚本，异常技能会标记「需处理」；
- 技能卡片与详情明确标注来源、只读原因、使用人数；只读来源说明为什么不能编辑 / 删除；
- 员工绑定只保存技能引用，技能修改后所有绑定员工同时生效；
- 运行时把绑定技能复制到 Agent 的隔离配置目录，实际加载结果写入运行产物。

### 6. MCP 服务管理

- **文件库**：`~/.novastudio/mcp/*.json`，一个服务一个文件，可直接查看、编辑、分享；
- 自动发现 Claude 用户配置（`~/.claude.json`）与项目级 `<项目>/.mcp.json`，统一归入「Claude 全局」，只读展示，可导入 Nova 库；
- 支持 stdio / HTTP / SSE：stdio 填命令、参数、环境变量，远程填 URL 与请求头；
- 环境变量与请求头支持 `${VAR}` 占位符，运行时从环境解析；字面量密钥会在列表标记「含密钥」；
- 服务卡片带来源、传输方式、只读、含密钥、使用人数等标签；
- 数字员工按引用绑定，运行时由 Nova 渲染成隔离的 Claude `mcp.json`；
- 其他 Agent 暂未适配，运行时会在告警中明确说明。

### 7. 知识库

把团队资料整理成 Agent 可复用的本地 Wiki：

- **文件库**：`~/.novastudio/knowledge/<知识库>/`，一个知识库一个目录，可直接用资源管理器管理；
- 左侧知识库列表 + 右侧文档两栏：支持新建、重命名、删除知识库，右键即可打开目录或管理；
- 知识库内支持子文件夹、多选上传与批量删除；
- 只接受 Markdown（`.md` / `.markdown`），单文件上限 100MB；同名文件自动加序号，不覆盖已有资料；
- Markdown 预览支持 GFM 表格与代码高亮，也可用系统程序打开原文件；
- 基于 SQLite FTS5（trigram）的全文检索，支持中文与英文子串匹配；
  - 检索词过短（少于 3 个字符）时自动降级为逐字匹配；
  - 可切换「当前知识库 / 全部知识库」，结果带高亮片段；
  - 超过 8MB 的文档不建全文索引，但仍在列表中可见、可注入；
- 数字员工按引用绑定，工作流节点执行前把知识库目录与文件清单写入系统提示词，Agent 按需读取；
- 已删除 / 空知识库会在运行告警中明确说明，不会阻断工作流。

### 8. 任务中心（自动化）

- 用自然语言创建任务，绑定项目与 Agent；
- 后台轮询自动拾取、创建会话并执行；
- 看板式状态：待执行 / 执行中 / 已完成 / 失败；
- 支持并发数、轮询间隔、单次运行超时配置；
- 执行详情直接跳转到对应会话。

### 9. 工作区与开发工具

- 工作区文件树，带 Git 状态标记（新增 / 修改 / 删除等）；
- 文件只读预览：文本、Markdown、图片、PDF、二进制；
- 点击文件在中间区域以标签页打开，可随时回到对话；
- 内置系统终端（node-pty），支持多标签、自定义工作目录；
- `@` 文件提及，快速把项目文件加入上下文。

### 10. 主题与个性化

- 内置 2 套皮肤：经典·昼、经典·夜；
- Shiki 代码高亮主题随皮肤联动；
- 界面字号、聊天字号可独立调整，文件预览与工作区文件跟随全局字号；
- 默认 Agent、默认工作目录、自动化并发、超时时间均可配置。

## 🧩 支持的 Agent

| Agent | 会话恢复 | 说明 |
|---|:---:|---|
| **Claude Code** | ✅ | 完整支持工具调用流式解析、历史回放、工作流独立配置隔离 |
| **Codex** | ✅ | 自动检测与多轮会话 |
| **OpenCode** | ✅ | 自动检测与多轮会话 |
| **Pi** | ✅ | 自动检测与多轮会话 |

> 新增 Agent 只需增加一个适配器目录，对话界面、会话管理、工作流引擎与 IPC 无需改动。
>
> 知识库通过系统提示词注入，对所有 Agent 生效；技能与 MCP 的运行时物化目前由 Claude Code 完整支持。

### Agent 配置（运行环境）

- 侧栏「运行环境 → Agent 配置」集中维护 Nova 自己的接入配置：Base URL、API Key、默认模型与模型清单；
- 自动检测本机是否安装 Claude Code；未安装时给出 npm 安装命令、一键复制与重新检测入口；
- 支持一键查询 `/v1/models`、连通性测试（Base URL + API Key + 模型名），以及「从本机 Claude 一次性导入」；
- 配置以 `~/.novastudio/agent-connections/claude/` 下的文件为准：`settings.json`（接入配置、别名映射，含明文 API Key）与 `models.json`（模型清单 + 默认模型）；渲染层只显示脱敏尾号；
- 保存时直接写文件；旧版本数据库中的加密记录只用于升级迁移，迁移完成后删除；
- 工作流节点执行时**直接复制 settings.json** 到隔离目录，并把该节点实际使用的模型写入副本的 `ANTHROPIC_MODEL`（Claude 的 settings.env 优先级高于 `--model`，不写入会导致员工绑定的模型失效）；宿主环境里的 `ANTHROPIC_*` 会被剔除；
- **运行期不读取本机 Claude 配置**；本机配置只在导入时读取一次。

## ⚡ 快速开始

> [!IMPORTANT]
> 需要 **Node.js 20+（推荐）**、**npm 9+**，以及至少一个本地 Agent CLI（Claude Code / Codex / OpenCode / Pi 任选其一）。
> 当前主要面向 Windows；其他平台可通过源码运行，但未做完整验证。

```bash
# 安装依赖
npm install

# 开发模式
npm run dev

# 构建 + 打包 Windows 安装包（产物在 release/）
npm run package:win
```

首次启动后：

1. Nova 会自动扫描本机已安装的 Agent；
2. 创建一个项目（选择一个工作目录）；
3. 直接对话，或继续创建数字员工、知识库与工作流。

---

## 🎯 五分钟上手

### 1. 创建项目

点击左侧「新建会话」，在会话页左栏点击「+」选择一个工作目录。项目既是聊天的工作目录，也是工作流的工作区。

### 2. 创建数字员工

进入「数字员工」，为不同角色配置：

- 绑定 Agent 与模型；
- 写清职责边界与输出要求；
- 按需启用 MCP、技能与知识库。

### 3. 创建知识库

进入「知识库」→「新建知识库」，然后在右侧上传 Markdown 文档；也可以新建子文件夹分类存放。

创建后回到「数字员工」→「知识库」标签页勾选引用。工作流执行到该员工时，Nova 会把知识库目录与文件清单写入系统提示词，Agent 会按需读取并引用。

### 4. 创建工作流

进入「工作流」→ 选择工作区 → 「新建工作流」。以一条常见的研发流水线为例：

```
开始 → 需求产品工程师 → 业务架构师 → 程序员 → 代码评审员 → 测试工程师 → 结束
```

点击左侧节点或数字员工即可加入画布，从节点右侧圆点拖出连线。

### 5. 调试

点击工作流卡片上的「调试」，或进入编辑器后点「调试」：

- 节点会在画布上实时变色；
- 顶部显示当前进度与当前节点；
- 人工审核节点会暂停，等待你通过或驳回；
- 可随时终止。

### 6. 查看运行记录与产物

点击「运行记录」：

- 列表展示每次执行的状态、开始时间、完成时间、总耗时；
- 点击详情查看每个节点的输入、返回、交接单和产物文件；
- 产物目录可直接打开。

## 📦 工作流产物

每次运行都会在工作区生成独立目录：

```
<workspace>/.novastudio/
└── workflows/<workflowId>/runs/<runId>/
    ├── run.json
    └── nodes/<nodeId>/attempt-1/
        ├── input.md              # 实际提交给 Agent 的输入
        ├── system-prompt.md      # 员工人设 / 系统提示词（含知识库清单）
        ├── output.md             # Agent 返回
        ├── handoff.md            # 结构化交接单
        ├── agent-options.json    # 模型 / MCP / 技能 / 知识库等运行参数
        ├── knowledge.json        # 本次注入的知识库与文件清单（如有）
        └── warnings.txt          # 隔离环境告警（如有）
```

- 不同工作流、不同运行互不覆盖；
- `.novastudio` 内置 `.gitignore`，不会污染业务仓库；
- 运行失败或被取消也会保留已产生的输入与产物，便于排查。

## 🔒 数据与安全

- **本地优先**：对话、员工、工作流、知识库与运行记录全部存储在 `~/.novastudio/`，不依赖外部服务；
- **知识库透明**：文档以 Markdown 明文存放，可直接用编辑器修改；全文索引保存在本地 SQLite，删除知识库会同步清理索引；
- **进程隔离**：渲染进程关闭 `nodeIntegration`，开启 `contextIsolation` 与 `sandbox`，Agent 子进程仅在主进程启动；
- **工作区隔离**：每个工作流运行有独立产物目录；Claude Code 节点使用独立配置目录，MCP 与技能按节点隔离；
- **Agent 配置**：配置以 `~/.novastudio/agent-connections/claude/` 下的文件为准（`settings.json` 含明文密钥，`models.json` 为模型缓存）；旧版本数据库中的加密记录只用于升级迁移，迁移完成后删除。请勿分享或提交该目录；
- **可审计**：每次运行保留输入、返回、交接单、运行参数、知识库清单与事件日志；
- **不会动你的业务目录**：删除工作区只清理 Nova 生成的内容，工作区文件夹本身不会删除。

> [!CAUTION]
> `~/.novastudio/` 存有全部会话与工作流记录，手动删除该目录会清空这些历史数据，且无法从 CLI 侧恢复。
