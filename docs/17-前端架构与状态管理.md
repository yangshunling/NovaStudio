# 17 前端架构与状态管理

## 1. 目的与边界

本层覆盖 React 渲染进程的整体结构：

- 应用壳与视图切换；
- Zustand 状态分域；
- IPC 客户端与事件订阅；
- 渲染性能策略（合批、节流、引用稳定、常驻挂载）；
- 通用 UI 组件与交互基础设施。

具体页面规格见 18，设计系统见 19。

## 2. 应用壳

文件：`src/renderer/App.tsx`

```tsx
<ErrorBoundary>
  <div className="flex h-screen w-screen overflow-hidden bg-bg text-text">
    <Sidebar />
    {viewMode === "automation" ? <AutomationView /> : ...}
    <div className={viewMode === "chat" ? "contents" : "hidden"}>
      <SessionsView />
      {showWorkspace && <WorkspacePanel />}
    </div>
    <div className={viewMode === "terminals" ? "contents" : "hidden"}>
      <TerminalsView />
    </div>
    <div className={viewMode === "workflow" ? "contents" : "hidden"}>
      <WorkflowsView />
    </div>
    {showSettings && <SettingsModal />}
    <ConfirmDialog />
    <ToastViewport />
  </div>
</ErrorBoundary>
```

### 2.1 视图切换

`viewMode` 来自 `chat` store：

```ts
type ViewMode =
  | "chat" | "terminals" | "automation" | "employees" | "workflow"
  | "triggers" | "skills" | "mcp" | "knowledge" | "workspaces" | "agents";
```

- `Sidebar` 调用 `setViewMode`；
- 会话 / 终端 / 工作流三页**常驻挂载**，只切换 `hidden`；
- 其他页面按需挂载。

### 2.2 为什么常驻挂载

| 页面 | 局部状态 |
|---|---|
| 会话 | 输入草稿、`@` 引用、滚动位置、文件标签、文件面板 |
| 终端 | 多个 PTY 进程、输出、选中工作区、文件面板 |
| 工作流 | 画布草稿、未保存状态、调试面板、缩放/平移 |

切换侧栏不应清空这些状态。

### 2.3 启动副作用

```ts
useEffect(() => {
  if (import.meta.env.DEV) validateSkins();
  detectAgents().catch(...);
  loadSkinSettings().catch(...);
  loadProjects().then(loadSessions).catch(...);
  loadTasks().catch(...);
  preloadAssets();
}, [detectAgents, loadProjects, loadSessions, loadTasks]);
```

- 开发模式校验皮肤 token；
- 检测 Agent；
- 加载皮肤 / 字号；
- 加载工作区 → 会话；
- 加载自动化任务；
- 预加载资产（MCP / Skill / 知识库），页面切换读缓存，外部变更用刷新按钮重扫。

### 2.4 全局弹层

- `ErrorBoundary`：捕获渲染错误，展示兜底；
- `ConfirmDialog`：替代 `window.confirm`，避免原生对话框抢焦点；
- `ToastViewport`：顶部居中提醒，所有页面共用。

## 3. 状态分域（Zustand）

| store | 文件 | 职责 |
|---|---|---|
| `useChatStore` | `stores/chat.ts` | Agent、工作区、会话、消息桶、流式状态、视图、设置弹框、文件面板 |
| `useAutomationStore` | `stores/automation.ts` | 自动化任务列表、状态更新 |
| `useAssetsStore` | `stores/assets.ts` | MCP / Skill / 知识库资产预加载与刷新 |
| `useEmployeesStore` | `stores/employees.ts` | 数字员工列表 |
| `useTerminalStore` | `stores/terminal.ts` | 终端标签、活动终端、重启计数 |
| `useFileViewerStore` | `stores/fileViewer.ts` | 文件预览标签、活动标签 |
| `useToastStore` / `toast` | `stores/toast.ts` | 全局提醒 |
| `useConfirmStore` / `confirmDialog` | `stores/confirm.ts` | 全局确认框 |
| `useThemeStore` | `hooks/useTheme.ts` | 皮肤、全局字号、聊天字号、终端字号 |

### 3.1 设计原则

1. **按域拆分**，不要一个巨型 store；
2. **按会话分桶**：`messagesBySession` / `streamingBySession`，多会话并发；
3. **选择器**：组件用 selector 订阅最小切片，避免每个 token 触发全树重渲染；
4. **动作稳定**：selector 取 action（函数引用稳定），避免 `useEffect` 依赖抖动；
5. **真值在主进程**：主题、设置、资产都以主进程 / 磁盘为准，store 是视图缓存。

### 3.2 `useChatStore` 关键切片

```ts
agents, projects, sessions,
currentProjectId, currentSessionId,
messagesBySession, streamingBySession,
loadingHistoryFor, selectedAgentId,
viewMode, showSettings, showWorkspace,
projectsLoaded, sessionsLoaded
```

选择器：

```ts
selectCurrentMessages(s)
selectCurrentStreaming(s)
selectEffectiveAgentId(s)
```

## 4. IPC 客户端

文件：`src/renderer/lib/ipc.ts`

```ts
const bridge = (window as { nova: NovaBridge }).nova;

function call<C extends IpcInvokeChannel>(channel: C, ...args: IpcArgs<C>): Promise<IpcResult<C>> {
  return bridge.invoke(channel, ...args);
}

function on<C extends IpcPushChannel>(channel: C, cb: (payload: IpcPushMap[C]) => void) {
  return bridge.subscribe(channel, cb);
}
```

对外暴露 `ipc` 对象：

- 语义化方法：`ipc.sendAgent`、`ipc.listSessions`；
- 订阅：`ipc.on.agentEvent`、`ipc.on.terminalData` 等，返回取消订阅函数。

**约定**：组件不直接调用 `window.nova.invoke`。

## 5. 事件订阅

文件：`src/renderer/hooks/useAgentStream.ts`

```ts
export function useAgentStream(): void {
  const _onEvent = useChatStore(s => s._onEvent);
  const _onDone = useChatStore(s => s._onDone);
  const _onTaskUpdated = useAutomationStore(s => s._onTaskUpdated);

  useEffect(() => {
    const unsubs = [
      ipc.on.agentEvent(payload => _onEvent(payload)),
      ipc.on.agentDone(data => _onDone(data)),
      ipc.on.agentsDetected(agents => useChatStore.setState({ agents })),
      ipc.on.automationUpdated(task => _onTaskUpdated(task)),
    ];
    return () => unsubs.forEach(unsub => unsub());
  }, [_onEvent, _onDone, _onTaskUpdated]);
}
```

`App` 顶层调用一次。

其他订阅按页面的 `useEffect` 注册 / 清理：

- `Sidebar`：`workflow:run:event` + 轮询活跃运行；
- `WorkflowsView` / `WorkflowRunView`：运行事件、节点实时事件；
- `TerminalsView`：终端数据 / 退出；
- `TerminalView`：按 `processId` 过滤；
- `TriggersView`：`triggers:updated`；
- 设置 / 关于：`updater:changed`。

## 6. 渲染性能

### 6.1 双层合批

- 主进程：`agent:event` 16ms 批量；
- 渲染层：`chat.ts` 16ms 合并成一次 `setState`。

### 6.2 Markdown 节流

`useThrottledValue` + `markdownInterval`：

- 短文本 80ms；
- 8KB+ 150ms；
- 16KB+ 200ms；
- 首个值立即生效，最后一次变化必提交。

### 6.3 `convertMessage` 引用稳定

`AssistantMessageList` 用 `useCallback`，依赖 `[streaming, messageCount]`。

**为什么**：assistant-ui 以回调引用作为转换缓存失效条件；每次渲染新建回调会导致每个 token 重新转换整个会话。

### 6.4 不重读全量历史

`_onDone` 在内存已有完整一轮时只刷新会话列表，不 `ipc.getSession` 整体替换。

**为什么**：替换会让全部消息对象换引用，转换缓存与 React 渲染全部失效。

### 6.5 常驻挂载

会话 / 终端 / 工作流只隐藏不卸载。

### 6.6 选择器订阅

```ts
const sessions = useChatStore(s => s.sessions);
const streamingBySession = useChatStore(s => s.streamingBySession);
```

不要 `useChatStore()` 无选择器订阅整个 store。

### 6.7 大文件图标

`vscodeFileIcons.ts` 是生成的图标数据（111KB），按需查表，不动态请求。

## 9. 主题与皮肤接入

- `useThemeStore` 在首次渲染前应用缓存皮肤与字号，避免 FOUC；
- `loadSkinSettings()` 在启动后从主进程同步；
- `applyTheme` 写 `<html data-theme>` 与 `color-scheme`，并通知主进程原生标题栏；
- `useSkin()` 返回完整 `SkinVariant`（codeTheme / appearance）；
- 组件只用语义 class 与 token，不出现硬编码颜色 / 字号。

详见 19。

## 10. 错误处理

| 层级 | 处理 |
|---|---|
| 渲染异常 | `ErrorBoundary` 兜底 |
| IPC reject | `try/catch` + toast |
| 业务失败 | 联合类型 `{ok:false}` + 页内提示 |
| 运行失败 | assistant 错误块 |
| 非致命 | assistant warning 块 |
| 确认操作 | `confirmDialog` |
