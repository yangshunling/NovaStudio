# 附录 C — 已知问题与设计取舍

> 本附录记录“源码里看起来不够完美、但有意为之或已知”的点。复刻时可以先照做，再决定是否改进。

---

## 1. 注释漂移

### 1.1 “正文不入库”

- `src/main/utils/paths.ts` 顶部注释；
- `src/shared/types.ts` 中 `Session.messageCount` 注释。

仍写“对话正文不入库 / 由 CLI 回放”，但实现已经改为：

- `messages` 表存完整 `AgentEvent[]`；
- `getSessionWithHistory` 优先读数据库；
- DB 无数据才回退 provider。

**以实现为准**。这两处是历史遗留注释。

### 1.2 任务中心“三列”

`AutomationView.tsx` 注释写“三列看板”，但 `AutomationStatus` 有 4 个状态：

- `pending`
- `running`
- `completed`
- `failed`

视觉上 `failed` 留在“执行中”列（失败态 + 手动重试），所以是三列。

### 1.3 “未归属”工作流

工作流必须有 `workspaceId`，但旧数据可能为空；列表用“未归属”分组兜底。

## 2. 单 Agent 限制

### 2.1 当前只有 Claude Code

`resolveAgentId()`：

```ts
function resolveAgentId(): string {
  const provider = listProviders()[0];
  if (!provider) throw new Error("未注册任何 Agent，无法执行工作流节点");
  return provider.manifest.id;
}
```

- 工作流节点固定使用第一个 provider；
- 节点级 Agent 选择已退化；
- 旧迁移代码仍会往 `node.config.agentId` 写值，但类型里已没有该字段，运行器也不读。

**为什么保留 provider 抽象**：未来新增 Agent 只需加目录，不改 engine / IPC / UI。

### 2.2 Agent 选择器

聊天页只在“已安装 Agent 数 > 1”时显示选择器；当前只有一个，所以默认不显示。

## 3. 工作流取舍

### 3.1 同一工作区同时只跑一条工作流

- `WorkspaceBusyError`；
- 触发器排队最多 30 分钟；
- 手动运行会直接被拒绝。

**原因**：并行写同一工作区文件风险高；Agent 进程也会互相干扰。

### 3.2 单工作流最多 3 个节点并行

`MAX_PARALLEL_NODES = 3`。

**原因**：每个节点是一个独立 Agent 进程，过多会打爆机器。

### 3.3 审核超时固定 30 分钟

`APPROVAL_TIMEOUT_MS = 30 * 60 * 1000`，不可配置。

**原因**：避免被遗忘的审批永久锁住工作区。

### 3.4 重试等待 N×2s

`RETRY_BASE_MS = 2000`，第 N 次重试等待 N×2 秒。

### 3.5 节点间只传 4000 字摘要

`UPSTREAM_SUMMARY_LIMIT = 4000`；完整内容让下游读产物文件。

**原因**：避免上下文爆炸。

### 3.6 修改轮最多 3 轮

`effectiveMaxRevisions` 夹在 0–3。

**原因**：防止无限修改循环。

### 3.7 实时事件不落库

- `workflow:run:agentEvent` 只推送；
- 内存上限 20000 条；
- 运行结束后以 `messages` 表为准。

**原因**：token 级事件落库会把事件表撑爆。

### 3.8 事件日志不随运行详情返回

`workflow:run:get` 只返回 run + nodes，不返回全量事件。

**原因**：长运行的每次刷新会变成全表读取。

## 4. 知识库限制

### 4.1 只收 Markdown

`.md` / `.markdown`；其他格式上传时拒绝。

**原因**：索引与提示词注入都基于纯文本。

### 4.2 超过 8MB 不建全文索引

- `INDEX_MAX_BYTES = 8MB`；
- 仍出现在文件列表、仍可注入提示词、仍可预览；
- 检索只按文件名（实际是“不参与内容检索”）。

### 4.3 单文件 100MB / 预览 2MB

- 上传上限 100MB；
- 预览读取上限 2MB，超出截断；
- 单库扫描上限 5000 文件 / 深度 12。

### 4.4 FTS5 trigram 的局限

- 支持中英文子串；
- 词长 < 3 时降级 LIKE（性能较低）；
- 不是语义检索，没有向量 / embedding；
- 检索词按空格拆分，AND 关系，不支持复杂查询语法。

### 4.5 检索前同步有 2 秒节流

外部编辑最多 2 秒后才被检索到；应用内上传 / 删除是即时更新。

### 4.6 不支持应用内新建文档

只能上传后编辑（Roadmap 项）。

## 5. MCP / Skill 限制

### 5.1 MCP 只扫描用户级顶层

- 不扫描项目级 `projects[<dir>].mcpServers`；
- 不扫描项目 `.mcp.json`。

**原因**：项目级属于具体工作区，纳入全局库会产生歧义。

### 5.2 MCP 配置可能被 Claude 同时写

- Nova 用原子写；
- 文件无法解析时拒绝写入；
- 但没有文件锁，极端并发下仍可能后写覆盖先写。

### 5.3 Skill frontmatter 只解析 name / description

- 不引入完整 YAML；
- 支持引号、`>` / `|`、全角冒号、CRLF；
- 复杂 YAML 结构（数组 / 嵌套）不支持。

### 5.4 Skill 只认 SKILL.md

- 没有 `SKILL.md` 的目录不是技能；
- 兼容 `SKILL.md.txt`；
- 文件树最多 500 项 / 深度 12。

### 5.5 所有技能可编辑 / 删除

不再区分 Nova 创建 / Claude 创建。误删 Claude 自带技能是可能的，删除前只有 UI 确认。

## 6. 平台特化

### 6.1 Windows 优先

- `claude` 通常是 `.cmd`，经 `cmd.exe` 解析；
- 自己拼命令行引号；
- `taskkill /T /F` 杀进程树；
- 路径大小写 / 分隔符归一化；
- NSIS 安装包。

macOS / Linux 可源码运行，但未完整验证。

### 6.2 终端 shell

- Windows：`powershell.exe -NoLogo`；
- 其他：`$SHELL` 或 `/bin/bash`。

### 6.3 终端固定纯黑

不随皮肤明暗切换。

**原因**：终端是唯一高对比工作台；与白色工区形成边界。

### 6.4 终端上限 12 个

`MAX_TERMINALS = 12`，每个工作区最多一个由前端 store 保证。

## 7. 安全 / 数据限制

### 7.1 代码签名关闭

`signAndEditExecutable: false`。安装包完整性依赖 GitHub 通道，没有本地签名校验。

### 7.2 无用户认证 / 权限系统

单机单用户；`~/.novastudio` 的读取权限依赖操作系统文件权限。

### 7.3 不扫描资产内容

MCP / Skill 是否恶意由用户自行判断；Nova 只做格式校验与路径安全。

### 7.4 凭证副本

工作流节点会复制 `.credentials.json` 到临时目录，`chmod 0600`，结束即删；但 Windows 下 `chmod` 基本无副作用。

### 7.5 单实例

多实例会互相干扰，强制单实例；代价是第二个实例只能聚焦已有窗口。

## 8. 前端取舍

### 8.1 常驻挂载

会话 / 终端 / 工作流页面常驻，切换只 `hidden`。

**代价**：内存占用更高；**收益**：不丢输入、PTY、画布草稿。

### 8.2 不使用路由库

`viewMode` 是 Zustand 里的枚举，没有 URL 路由。

**代价**：不能深链接；**收益**：Electron 单窗口场景够用，状态简单。

### 8.3 assistant-ui 适配层

- 只借用展示运行时；
- 输入框仍由 Nova 管理；
- `convertMessage` 引用稳定是性能关键。

### 8.4 自绘画布

不引入第三方图库；拖拽 / 缩放 / 连线 / 多选都是手写。

**代价**：功能边界有限；**收益**：无额外依赖、样式完全可控。

### 8.5 没有虚拟列表

会话消息、知识库文档、技能文件树都是普通渲染，超过一定规模可能卡顿。

### 8.6 没有 E2E 测试

只有纯函数 / 模块单测；UI 与主进程集成靠手工验收。

## 9. 数据 / 迁移取舍

### 9.1 迁移是“加列 + 检测”

- 新装用户走全量 `CREATE TABLE`；
- 旧库用 `PRAGMA table_info` 检测缺列后 `ALTER`；
- 一次性数据迁移用 `settings` 里的 marker 防重复。

**代价**：迁移代码与建表代码可能漂移；需要保持同步。

### 9.2 员工表重建

旧版员工有 `agent_id` / `model` 列，迁移时重建表去掉它们。

### 9.3 旧目录归档

`~/.nova` → `~/.novastudio` 一次性 rename；
旧 MCP / Skill → Claude 配置后移到 `~/.novastudio/legacy-assets/<时间戳>`。

### 9.4 应用异常退出

- 启动时把 `running` / `awaiting_approval` 运行标记为 `interrupted`；
- 节点标记为 `canceled`；
- 自动化 `running` 任务标记为 `failed`。

## 10. 性能取舍

| 策略 | 代价 | 收益 |
|---|---|---|
| 16ms 主进程合批 | 事件延迟最多 16ms | 减少 IPC 抖动 |
| 16ms 渲染层合批 | 同样延迟 | React 更新降到帧率同阶 |
| Markdown 节流 | 长文本刷新变慢 | 主线程不被占满 |
| `convertMessage` 缓存 | 需要稳定引用 | 不整段重转 |
| 不重读全量历史 | 极少数情况需兜底回读 | 避免结束瞬间卡顿 |
| 常驻挂载 | 内存高 | 状态不丢 |
| 知识库 2s 同步节流 | 外部编辑延迟 | 避免每次输入全量扫描 |

## 11. 已知但未修的边界

1. **`Session.messageCount` 可能虚高**：运行失败撤回、用户停止等场景已在 handler 处理，但极端并发下仍可能有偏差。
2. **MCP 改名与 Claude 同时写**：没有文件锁，极端情况下可能覆盖。
3. **知识库外部删除**：检索前同步会清理索引，但文件列表缓存最多 1 秒。
4. **Skill 删除无回收站**：直接 `rm -rf`。
5. **工作流运行中编辑工作流**：本次运行使用快照，不受影响；但续跑使用 `run.graph`，不是最新编辑。
6. **审核等待期间关闭应用**：运行标记 interrupted，节点 canceled；回来可续跑。
7. **终止运行后子进程可能延迟退出**：`taskkill` 后仍有 1.5 秒兜底。
8. **终端 PTY 输出不落库**：切换页面靠常驻挂载保留，重启应用丢失。
9. **自动化任务 failed 留在“执行中”列**：视觉上容易误解为仍在运行。
10. **没有全局搜索**：会话 / 工作流 / 知识库各自搜索。
