# 19 设计系统与皮肤

## 1. 目的与边界

Nova 的设计系统目标：

> 换肤只切换 `<html data-theme>`，组件代码零改动；所有颜色 / 字号 / 间距 / 尺寸 / 动效都来自 token。

包含：

- 皮肤契约与注册表；
- token 分层与清单；
- 派生字号量表；
- Tailwind 映射；
- `ui-*` 结构原语；
- 主题状态与明暗切换；
- Shiki 代码高亮联动；
- 校验机制；
- 新增一套皮肤的步骤。

---

## 2. 皮肤 = 一份元数据 + 一份 token 文件

```
src/renderer/skins/
├── contract.ts          # token 契约（唯一真相来源）
├── registry.ts          # 自动收集 skins/*/index.ts
├── validate.ts          # 开发期运行时校验
├── _base.css            # 所有皮肤共享的形状默认值
├── classic-day/
│   ├── index.ts         # SkinVariant
│   └── tokens.css       # 该皮肤独有的调色
└── classic-night/
    ├── index.ts
    └── tokens.css
```

### 2.1 `SkinVariant`

```ts
export interface SkinVariant {
  id: string;
  displayName: string;
  description: string;
  appearance: "light" | "dark";
  codeTheme: string;   // Shiki 主题名
  order: number;
}
```

- `id` 写入 `<html data-theme>` 与设置；
- `appearance` 驱动原生控件配色（`color-scheme` / 原生标题栏）；
- `codeTheme` 由皮肤自己指定，宿主不推断；
- `order` 决定列表顺序，第一套为默认。

### 2.2 注册表

```ts
const modules = import.meta.glob<{ variant: SkinVariant }>("./*/index.ts", { eager: true });
export const skins = Object.values(modules).map(m => m.variant).sort((a, b) => a.order - b.order);
export const defaultSkinId = skins[0].id;
export function getSkin(id: string) { return skins.find(s => s.id === id) ?? skins[0]; }
```

- 新增皮肤 = 新增目录，registry / 组件 / 高亮 / 设置零改动；
- 未知 id 回退默认，避免旧设置导致白屏。

## 3. Token 分层

### 3.1 `_base.css`

所有皮肤共享的**形状默认值**：

- 字体栈（sans / mono 使用系统默认字体；display 仅侧栏品牌刊头使用）；
- 圆角刻度（sm 4 / md 6 / lg 8 / xl 12 / 2xl 12，另有 full 与 btn 两个专用口子）；
- 布局尺寸（侧栏 / 列表 / 工作区 / 抽屉 / 顶栏 / 内容宽度 / 弹框 / 菜单）；
- 间距角色（inset / card / section / field）；
- 控件尺寸（avatar / icon button）；
- 动效时长与缓动；
- Agent 标识色默认值。

使用：

```css
:where([data-theme]) {
  --c-radius-sm: 4px;
  --c-radius-md: 6px;
  --c-radius-lg: 8px;
  --c-radius-xl: 12px;
  --c-radius-2xl: 12px;
  --c-radius-input: var(--c-radius-lg);
  --c-radius-bubble: var(--c-radius-2xl);
  --c-btn-radius: var(--c-radius-lg);
  --c-radius-full: 999px;
}
```

组件里只写 `rounded-sm / md / lg / xl / 2xl / full`，禁止 `rounded-[6px]` 这类任意值。

**为什么用 `:where()`**：

- `_base.css` 被每套皮肤 `@import`，会内联多次，声明顺序不可控；
- `:where()` 把特异性归零（0,0,0）；
- 皮肤自己的 `[data-theme="<id>"]` 是 (0,1,0)，总是覆盖 base，与加载顺序无关；
- 若用 `:root`（同为 0,1,0），换肤结果会依赖打包顺序。

### 3.2 `<id>/tokens.css`

该皮肤独有的调色与刻意差异：

- 背景 / 表面 / 玻璃 / 边框；
- 文本 / 强调 / 语义色；
- 用户气泡；
- 输入框；
- 滚动条；
- 阴影；
- 主 / 次 / 圆形按钮；
- 芯片；
- 侧栏 / 面板；
- 进度条；
- 可选：`--c-page-bg` / `--c-page-shadow` / `--c-page-inset` / `--c-panel-bg`。

### 3.3 分层规则

| 层 | 谁提供 | 内容 |
|---|---|---|
| 派生 | `styles/index.css` | 字号量表，从 `--c-font-size` 计算 |
| 形状默认 | `_base.css` | 字体栈 / 圆角 / 布局 / 间距 / 尺寸 / 动效 |
| 皮肤调色 | `<id>/tokens.css` | 颜色与刻意差异 |

**新增 token 时要改三处**：

1. `skins/contract.ts` 的清单；
2. `styles/index.css` 的 `@theme inline` 映射（如果是 Tailwind 工具类）；
3. `_base.css` 的默认值（如果所有皮肤共享）。

## 5. 派生字号

```css
:root,
.ui-chat-scale {
  --c-font-size-micro: calc(var(--c-font-size) - 3px);
  --c-font-size-caption: calc(var(--c-font-size) - 2px);
  --c-font-size-meta: calc(var(--c-font-size) - 1px);
  --c-font-size-body: var(--c-font-size);
  --c-font-size-body-lg: calc(var(--c-font-size) + 1px);
  --c-font-size-title: calc(var(--c-font-size) + 2px);
  --c-font-size-heading: calc(var(--c-font-size) + 3px);
  --c-font-size-display: calc(var(--c-font-size) + 5px);
  --c-font-size-hero: calc(var(--c-font-size) + 7px);
}
```

- 基准 13px → 10 / 11 / 12 / 13 / 14 / 15 / 16 / 18 / 20；
- 用户调整全局字号时整套 UI 等比缩放。

### 5.1 聊天字号独立

```css
:root {
  --c-chat-font-size: var(--c-font-size);
}
.ui-chat-scale {
  --c-font-size: var(--c-chat-font-size);
}
```

- 聊天区子树在自身上重新声明 `--c-font-size`；
- 因此聊天区字号与全局解耦，其余界面不受影响；
- 自定义属性的 `var()` 在“声明它的元素”上替换，所以必须在 `.ui-chat-scale` 上重声明整张量表。

### 5.2 排版角色（组件选择字号的唯一入口）

9 档字号是「原料」，组件**不按像素挑字号**，而是按角色使用。角色表是排版一致性的唯一约定：

| 角色类 | 字号 | 字族 | 字重 | 用途 |
|---|---|---|---|---|
| `ui-type-prose` | body-lg | sans | — | Markdown 正文（固定 1.65 行高） |
| `ui-type-body` | body | 继承 | — | 正文 / 表单值 |
| `ui-type-item` | body-lg | 继承 | — | 列表项标题、用户气泡、输入框（单行 14px） |
| `ui-type-note` | meta | 继承 | — | 说明文字、卡片描述 |
| `ui-type-label` | meta | 继承 | 500 | 标签、字段名、按钮 |
| `ui-type-sub` | caption | 继承 | — | 副标题、时间、计数 |
| `ui-type-micro` | micro | 继承 | — | 仅白名单（工具参数等极密信息） |
| `ui-type-code` | meta | mono | — | 路径、ID、命令、代码 |
| `ui-type-code-sm` | caption | mono | — | 密集机器标识 |
| `ui-type-title` | title | sans（系统默认） | 600 | 页头 / 弹窗 / 卡片标题 |
| `ui-type-heading` | heading | sans（系统默认） | 600 | 内容区标题、空态标题 |
| `ui-type-display` | display | sans（系统默认） | 700 | Markdown h1 |
| `ui-type-hero` | hero | sans（系统默认） | — | 待办页日期大字（白名单） |
| `ui-type-brand` | hero | display（展示衬线） | — | **仅侧栏品牌刊头** |

约定：

1. **正文用 `body` / `prose` / `item`**，不用 `note` / `sub` 冒充正文；
2. **`mono` 只用于机器可读内容**（路径 / ID / 命令 / 代码），不用于整段中文说明；
3. **`micro` / `display` / `hero` / `brand` 是白名单档位**，只允许出现在约定位置；
4. 所有标题与正文使用**系统默认 sans**（`--c-font-sans`）；
   正文档位（body / item / note / label / sub / micro）只声明字号，字族继承默认；
   `prose` / `code` / `title` / `heading` / `display` / `hero` / `brand` 才显式声明字族。
   **展示衬线（`--c-font-display`）只属于 `brand`**，且只允许在侧栏品牌刊头出现，
   不再提供 `font-display` 工具类。
   行高与其余字重仍用工具类，避免迁移角色时改变既有节奏；
5. 单个文件的正文档位（body / item / note / label / sub / micro / code / code-sm）
   不超过 7 个；标题类不计入密度；
6. 禁止 Tailwind 默认字号（`text-xs` / `text-sm` / `text-lg` …）与任意值（`text-[13px]`）；
7. 聊天正文使用 `prose` / `item`，随 `.ui-chat-scale` 独立缩放。

守卫：`npm run verify:type`（`--strict` 时违规即失败）。

  --color-accent: var(--c-accent);

  --color-input-bg: var(--c-input-bg);

  --font-mono: var(--c-font-mono);

  --text-micro: var(--c-font-size-micro);
  --text-body: var(--c-font-size-body);

## 7. `ui-*` 结构原语

`styles/index.css` 定义与皮肤无关的构件：

| 类 | 作用 |
|---|---|
| `.ui-btn` | 按钮基座（高度 / 内边距 / 圆角 / 过渡） |
| `.ui-btn-sm` / `.ui-btn-xs` | 中 / 小号 |
| `.ui-btn-primary` | 主按钮 |
| `.ui-btn-ghost` | 次级按钮 |
| `.ui-btn-danger` / `.ui-btn-danger-soft` / `.ui-btn-danger-link` | 危险操作 |
| `.ui-btn-round` | 圆形图标按钮 |
| `.ui-icon-action` | 面板头部图标按钮 |
| `.ui-glass` / `.ui-glass-strong` | 玻璃拟态 |
| `.ui-ring` | 描边芯片 |
| `.ui-bubble` | 助手气泡 |
| `.ui-chat-gutter` | 聊天区左右内边距（头像槽） |
| `.ui-chat-avatar-left` / `right` | 头像绝对定位 |
| `.ui-scroll-hidden` | 隐藏滚动条保留滚动 |
| `.xterm` 相关 | 终端滚动条 / 背景 / padding |

**原则**：这些原语只消费 token，皮肤文件不需要写覆写规则。

## 8. 主题状态

文件：`src/renderer/hooks/useTheme.ts`

### 8.1 真值来源

- 真值在主进程设置（SQLite `settings`）；
- `localStorage` 只作为启动缓存，避免首帧 FOUC。

### 8.2 启动

```ts
const cached = readCache();
export const useThemeStore = create(...);

// 首次渲染前应用缓存
applyTheme(getSkin(useThemeStore.getState().currentTheme));
applyFontSize(useThemeStore.getState().fontSize);
applyChatFontSize(useThemeStore.getState().chatFontSize);
```

`App` 启动后调用 `loadSkinSettings()`，以主进程设置为准并回写缓存。

### 8.3 应用主题

```ts
function applyTheme(skin: SkinVariant) {
  const root = document.documentElement;
  root.setAttribute("data-theme", skin.id);
  root.style.colorScheme = skin.appearance;
  void ipc.setWindowAppearance(skin.appearance);
}
```

- `data-theme` 驱动 CSS 变量；
- `color-scheme` 让滚动条 / 原生 select / 输入光标跟随明暗；
- 通知主进程 `nativeTheme`，原生标题栏与系统控件跟随。

### 8.4 字号

```ts
applyFontSize(px)       // 写 --c-font-size 到 <html>
applyChatFontSize(px)   // 写 --c-chat-font-size
```

内联样式优先级高于皮肤规则，用户设置覆盖皮肤默认值。

### 8.5 缓存

```json
{ "theme": "classic-day", "fontSize": 13, "chatFontSize": 13 }
```

- 损坏 / 非法值回退默认；
- 老缓存没有 `chatFontSize` 时跟随全局，保证升级观感不变。

## 9. Shiki 代码高亮

文件：`src/renderer/lib/shiki.ts`

- 单例 `Highlighter`，首次调用异步初始化；
- 预加载语言：python / js / ts / tsx / jsx / bash / shell / json / html / css / go / rust / java / c / cpp / sql / yaml / markdown / xml / diff；
- 预加载主题：所有 `SkinVariant.codeTheme` 的并集（新增皮肤自动带上）；
- `highlightCodeSync` 在高亮器未就绪时返回 `null`，调用方 fallback 到纯文本；
- 语言 / 主题不在已加载列表时回退 `text` / 第一个主题。

**约定**：组件不硬编码主题名，一律从 `useSkin().codeTheme` 取。

## 10. 校验

### 10.1 开发期运行时

`skins/validate.ts`：

- 创建不可见探针元素；
- 依次设置 `data-theme`；
- 读取 `getComputedStyle`；
- 检查 `REQUIRED_TOKENS` 是否都能解析出非空值；
- 缺失在控制台报警。

**为什么用探针**：皮肤选择器是 `[data-theme="<id>"]`，不只匹配 `<html>`；探针可精确取样，不造成界面闪烁。校验的是最终计算值，`_base.css` 的默认值也算“能解析”。

### 10.2 构建后脚本

`npm run verify:skins` → `scripts/verify-skin-tokens.mjs`：

1. 读取构建产物 CSS；
2. 从 `contract.ts` 解析三份 token 清单；
3. 发现磁盘上的皮肤目录；
4. 检查 `_base.css` 使用 `:where([data-theme])`；
5. 每套皮肤：base + skin 合并后是否覆盖全部必填 token；
6. 反向守卫：CSS 里出现的每个 `--c-*` 都必须登记在契约里。

**三件事**：

- 每套皮肤能解析全部必填 token；
- base 用 `:where()` 归零特异性，覆盖关系不依赖加载顺序；
- 没有“没人管的临时变量”。

## 11. 新增一套皮肤

1. 新建 `src/renderer/skins/<id>/index.ts`：

```ts
import "./tokens.css";
import type { SkinVariant } from "@shared/contracts/skin";

export const variant: SkinVariant = {
  id: "<id>",
  displayName: "…",
  description: "…",
  appearance: "light" | "dark",
  codeTheme: "github-light" | "github-dark" | …,
  order: 30,
};
```

2. 新建 `tokens.css`：

```css
@import "../_base.css";

[data-theme="<id>"] {
  --c-bg: …;
  ...
}
```

3. 运行 `npm run build && npm run verify:skins`；
4. 开发模式启动，控制台检查 `[skin]` 报警；
5. 不需要改 registry、组件、高亮、设置面板。

## 13. 无障碍与动效

- 焦点可见：`.ui-btn:focus-visible` 使用 `outline` + `accent`；
- 危险按钮焦点色使用 `error`；
- 动效时长与缓动由皮肤 token 控制，组件只声明过渡属性；
- `prefers-reduced-motion` 的兜底在各使用处单独处理；
- 文本对比度：Agent 标识色对白底 / 深底约 4:1；
- 所有可点击元素有 `title` / `aria-label`；
- 原生控件配色随 `color-scheme`。
