## 4. electron-vite 配置

文件：`electron.vite.config.ts`

```ts
export default defineConfig({
  main: {
    plugins: [externalizeDepsPlugin()],
    build: {
      rollupOptions: {
        input: { index: resolve(__dirname, "src/main/index.ts") },
        output: { format: "es" },
      },
    },
  },
  preload: {
    plugins: [externalizeDepsPlugin()],
    build: {
      rollupOptions: {
        input: { index: resolve(__dirname, "src/preload/index.ts") },
        output: { format: "cjs" },
      },
    },
  },
  renderer: {
    root: "src/renderer",
    resolve: {
      alias: {
        "@shared": resolve(__dirname, "src/shared"),
        "@renderer": resolve(__dirname, "src/renderer"),
      },
    },
    plugins: [react(), tailwindcss()],
    build: {
      minify: "esbuild",
      rollupOptions: {
        input: { index: resolve(__dirname, "src/renderer/index.html") },
        output: {
          // 按 assistant-ui / markdown / react / shiki / xterm / icons 等拆分 vendor chunk
          manualChunks(id) {
            /* ... */
          },
        },
      },
    },
  },
});
```

### 4.1 关键点

1. **主进程输出 ESM**（`out/main/index.js`）。
2. **preload 输出 CJS**（`out/preload/index.cjs`）。原因：Electron sandbox 模式下 preload 只能是 CJS。
3. **渲染层 root 是 `src/renderer`**，所以 HTML 在 `src/renderer/index.html`。
4. **别名** `@shared` / `@renderer` 只在 Vite 与 tsconfig 中配置；主进程代码主要用相对路径。
5. **externalizeDepsPlugin** 让 Node 原生依赖（better-sqlite3、node-pty）不被打包，运行时从 `node_modules` 加载。

### 4.2 preload 路径解析

开发和构建模式下 preload 扩展名不同：

- dev：`out/preload/index.mjs`
- build：`out/preload/index.cjs`

`src/main/index.ts` 的 `resolvePreloadPath()` 按 `index.mjs → index.cjs → index.js` 顺序查找实际存在的文件。

## 5. TypeScript 配置

文件：`tsconfig.json`

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "jsx": "react-jsx",
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true,
    "noImplicitReturns": true,
    "esModuleInterop": true,
    "allowSyntheticDefaultImports": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "resolveJsonModule": true,
    "isolatedModules": true,
    "noEmit": true,
    "allowImportingTsExtensions": true,
    "baseUrl": ".",
    "paths": {
      "@shared/*": ["src/shared/*"],
      "@renderer/*": ["src/renderer/*"]
    }
  },
  "include": ["src/**/*", "electron.vite.config.ts"]
}
```

### 5.1 严格模式注意事项

- `noUnusedLocals` / `noUnusedParameters`：未使用变量会报错，复刻时不要留占位参数。
- `noImplicitReturns`：所有分支必须返回值。
- `noFallthroughCasesInSwitch`：switch 不允许穿透。
- `noEmit`：类型检查与构建分离，构建由 electron-vite 负责。

## 7. 路径别名与导入约定

### 7.1 别名

| 别名 | 指向 | 使用场景 |
|---|---|---|
| `@shared/*` | `src/shared/*` | 渲染层引用共享类型与纯函数 |
| `@renderer/*` | `src/renderer/*` | 渲染层内部绝对导入（较少使用） |

主进程基本使用相对路径（如 `../../shared/types`），因为 electron-vite 主进程没有配置别名；仅个别类型导入沿用了 `@shared/*`（如 `ipc/handlers/dialog.ts`）。

### 7.2 导入分层规则

- `shared/` 不能导入 `main/` 或 `renderer/`。
- `preload/` 只能导入 `shared/contracts/ipc` 的类型。
- `renderer/` 不能导入 `main/`；一切通过 `src/renderer/lib/ipc.ts`。
- `main/` 可以导入 `shared/`，不能导入 `renderer/`。

## 8. 构建与打包配置

文件：`package.json` 的 `build` 字段。

```json
{
  "appId": "com.nova.app",
  "productName": "NovaStudio",
  "directories": { "output": "release" },
  "files": ["out/**/*", "package.json"],
  "extraResources": [{ "from": "resources", "to": "resources" }],
  "publish": [{
    "provider": "github",
    "owner": "yangshunling",
    "repo": "NovaStudio",
    "releaseType": "release"
  }],
  "win": {
    "target": ["nsis"],
    "icon": "resources/logo.png",
    "signAndEditExecutable": false
  },
  "nsis": {
    "oneClick": false,
    "allowToChangeInstallationDirectory": true,
    "artifactName": "NovaStudio-Setup-${version}-${arch}.exe"
  }
}
```

### 8.1 关键点

- 只打包 `out/` 与 `package.json`；源码不进入安装包。
- `resources/` 作为 extraResources 复制到安装目录的 `<resourcesPath>/resources/`。
- 关闭代码签名（`signAndEditExecutable: false`），避免无证书环境打包失败。
- NSIS 非一键安装，允许用户选择安装目录。
- 发布渠道是 GitHub Releases，`electron-updater` 读取打包生成的 `app-update.yml`。

## 9. 环境变量

| 变量 | 作用 | 设置方 |
|---|---|---|
| `ELECTRON_RENDERER_URL` | dev server 地址；存在时窗口加载 URL，否则加载文件 | electron-vite |
| `NOVA_DEVTOOLS` | 设为 `1` 时启动自动打开 DevTools | 开发者 |

## 10. 代码风格与工程约定

从源码中可观察到的约定，复刻时建议保持一致：

1. **中文注释**：每个模块顶部有职责说明，关键分支解释“为什么”。
2. **工厂函数而非 class**：`createAgentService`、`createWorkflowRunner`、`createScheduler`、`createTerminalManager` 等；只有错误类型用 class（`GraphValidationError`、`WorkspaceBusyError`、`CanceledError`、`ApprovalTimeoutError`）。
3. **依赖注入**：`emit`、`push`、`flushEvents`、`userDataDir` 通过参数注入，便于测试与解耦。
4. **类型安全优先**：IPC 通道、数据库行映射、错误类型都尽量在编译期约束。
5. **注释解释“坑”**：例如 Windows 换行截断、事件重复、工作区竞争窗口。
6. **文件名即职责**：`catalog.ts` 管资产扫描，`runtime.ts` 管运行时解析，`runner.ts` 管执行。
7. **错误用类型区分语义**：`WorkspaceBusyError` 用于调度器判断是否排队，不依赖文案。
8. **来源标注**：注释里常见 `provider` / `宿主` / `渲染层` 的职责划分。
