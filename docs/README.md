# Nova Studio 工程文档

> 本目录的目标不是“介绍项目”，而是**让一个不了解该工程的 AI 或工程师，能够按文档从零复刻出同等行为的系统**。
>
> 文档以当前 `master` 分支源码为唯一事实来源。源码与文档冲突时，以源码为准，并应回头修正文档。

## 三、复刻总路线（摘要）

完整细节见 [24-复刻实施指南](24-复刻实施指南.md)。

| 里程碑 | 交付物 | 验收标准 |
|---|---|---|
| M0 脚手架 | Electron + React + TS + Tailwind + electron-vite 可启动 | `npm run dev` 出现窗口 |
| M1 数据与通信 | SQLite 表结构、IPC 契约、类型安全桥接 | 渲染进程可调用一个测试通道 |
| M2 Agent 与聊天 | Claude provider、会话、流式事件、历史回放 | 能与本机 Claude Code 多轮对话 |
| M3 员工与资产 | 数字员工、MCP、Skill、知识库 | 员工可绑定三类资产并查看 |
| M4 工作流 | 图校验、DAG 调度、运行记录、审核、产物 | 能跑通“开始→员工→结束”并留下产物 |
| M5 自动化与触发器 | 任务中心、定时触发 | 任务能自动执行，触发器能按规则启动工作流 |
| M6 工作区与终端 | 文件树、预览、Git 状态、PTY 终端 | 可在工作区浏览文件并开终端 |
| M7 前端完整化 | 11 个主视图、皮肤、设置 | 所有页面可用，两套皮肤可切换 |
| M8 工程化 | 打包、更新、测试 | `npm run package:win` 产出安装包，测试全绿 |

## 四、文档写作约定

每篇文档尽量遵循同一结构：

1. **模块目的与边界**：解决什么问题，不解决什么。
2. **数据结构 / 类型 / Schema**：字段、约束、默认值。
3. **对外接口**：IPC 通道或函数签名。
4. **核心流程**：Mermaid 时序图 / 状态机。
5. **关键算法**：伪代码或逐步说明。
6. **边界条件与坑**：并发、超时、取消、Windows、路径逃逸等。
7. **源码索引**：`文件:行号` 对照。
8. **复刻验收清单**：做到什么程度算复刻成功。

### 事实分级

- **事实**：直接来自源码，标注文件与行号。
- **推断**：源码未明说，但由行为推导，文档会注明“推断”。
- **取舍**：作者的设计选择，文档会解释“为什么这样而不是那样”。

### 图与代码

- 架构、时序、状态机优先用 Mermaid。
- 关键结构贴真实类型定义或 DDL，而不是重新描述。
- 算法给伪代码，语言无关。

## 五、如何用这些文档驱动 AI 复刻

推荐给 AI 的提示词模板：

```
你是一位资深 Electron/React/TypeScript 工程师。
请严格按照 docs/ 下的文档，从零复刻 Nova Studio。

要求：
1. 先读 docs/README.md、00、01、02，输出你的实现计划；
2. 按 docs/24-复刻实施指南.md 的里程碑逐阶段实现；
3. 每完成一个里程碑，对照该阶段的验收清单自检；
4. 遇到文档与源码冲突，以 docs 中的“事实”章节为准；
5. 不要省略：数据库 schema、IPC 契约、状态机、边界条件；
6. 每个模块完成后补对应测试。
```

## 六、维护约定

- 新增功能时，至少更新对应的模块文档 + `04-IPC契约参考` + `03-数据模型与数据库`（若有 schema 变化）。
- 新增页面时，更新 `18-页面与交互规格`。
- 新增设计 token 时，更新 `19-设计系统与皮肤`。
- 新增源文件时，更新 `附录/B-源码文件职责清单`。
- 文档中的行号会随代码变化而漂移；行号只用于快速定位，不作为长期契约。
