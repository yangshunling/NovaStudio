# 21 安全与数据隔离

## 1. 安全模型总览

Nova 是本地优先的单用户桌面应用，安全边界主要有四层：

1. **Electron 进程隔离**：渲染进程无 Node 能力，所有敏感操作在主进程；
2. **IPC 信任边界**：渲染层传入的路径 / ID / 参数一律不可信，主进程重新校验；
3. **文件系统边界**：项目文件、知识库、技能目录、会话目录都做越界校验；
4. **凭证与临时数据**：工作流节点的配置副本用完即删，启动时清理异常残留。

没有云端账号、没有远程同步、没有多用户权限系统。

---

## 2. Electron 安全配置

文件：`src/main/index.ts`

```ts
new BrowserWindow({
  webPreferences: {
    preload: preloadPath,
    nodeIntegration: false,
    contextIsolation: true,
    sandbox: true,
    backgroundThrottling: false,
  },
});
```

| 配置 | 作用 |
|---|---|
| `nodeIntegration: false` | 渲染进程不能 `require` / 访问 Node API |
| `contextIsolation: true` | preload 与页面上下文隔离 |
| `sandbox: true` | preload 运行在 sandbox，只能用受限 API |
| `backgroundThrottling: false` | 后台流式不节流（功能需要，非安全项） |

### 2.1 Preload 最小暴露

`src/preload/index.ts` 只暴露：

```ts
const api = { invoke, subscribe };
contextBridge.exposeInMainWorld("nova", api);
```

没有 `fs`、`child_process`、`shell` 等原始能力。

### 2.2 导航守卫

```ts
win.webContents.setWindowOpenHandler(({ url }) => {
  if (/^https?:\/\//i.test(url)) void shell.openExternal(url);
  return { action: "deny" };
});

win.webContents.on("will-navigate", (event, url) => {
  if (url === win.webContents.getURL()) return;
  event.preventDefault();
  if (/^https?:\/\//i.test(url)) void shell.openExternal(url);
});
```

- 远程页面不能在本窗口打开（否则能拿到 preload 的 IPC）；
- 外链交给系统浏览器。

### 2.3 单实例

```ts
if (!app.requestSingleInstanceLock()) app.quit();
```

**为什么**：多实例会互相把对方的运行记录标记为“已中断”，并可能同时写 SQLite / `~/.claude`。

## 3. IPC 信任边界

主进程不能假设调用方一定是本项目界面。每个 handler 都要重新校验：

- 项目 / 工作区是否存在；
- 路径是否在允许范围内；
- 名称 / ID 格式；
- 资产是否仍存在；
- 运行状态是否允许该操作。

示例：

```ts
handle("terminal:create", ({ id, cwd, cols, rows }) => {
  if (typeof id !== "string" || !id.trim()) throw new Error("终端标识无效");
  return createTerminal(id, resolveWorkspaceCwd(cwd), cols, rows);
});
```

`resolveWorkspaceCwd` 要求 `cwd` 必须等于某个已登记工作区的 `cwd`，否则拒绝。**否则渲染层可以传任意路径，在任意目录起 shell。**

## 4. 文件系统边界

### 4.1 路径工具

文件：`src/main/utils/paths.ts`

```ts
export const DATA_DIR = join(homedir(), ".novastudio");
export const DB_PATH = join(DATA_DIR, "data.db");

export function isInside(root: string, target: string): boolean {
  const rel = relative(root, target);
  return rel === "" || (!rel.startsWith("..") && !isAbsolute(rel));
}

export function resolveInside(root: string, relativePath: string): string | null {
  const target = resolve(root, relativePath);
  return isInside(root, target) ? target : null;
}

export async function isInsideReal(root: string, target: string): Promise<boolean> {
  const realRoot = await realpath(root);
  const realTarget = await realpath(target);
  return isInside(realRoot, realTarget);
}

export async function resolveInsideReal(root, relativePath): Promise<string | null> {
  const target = resolveInside(root, relativePath);
  if (!target) return null;
  return (await isInsideReal(root, target)) ? target : null;
}
```

**双重校验**：

- 词法层：`resolve` + `relative`，挡住 `../`；
- 真实路径层：`realpath`，挡住符号链接 / junction 逃逸。

### 4.2 项目文件

`files/access.ts`：

```ts
async function projectRoot(projectId) {
  const project = db.getProject(projectId);
  if (!project?.cwd) throw new Error("项目不存在或未配置工作目录");
  return realpath(project.cwd);
}

async function resolveInside(root, candidate) {
  if (!isInside(root, candidate)) throw new Error("文件路径超出项目目录");
  const fullPath = await realpath(candidate);
  if (!isInside(root, fullPath)) throw new Error("文件路径超出项目目录");
  return fullPath;
}
```

`file:read` / `file:openExternal` / `file:readEmbeddedImage` 全部走这套。

### 4.3 知识库

```ts
function resolveRelative(root, relativePath) {
  const normalized = relativePath.replace(/\\/g, "/").replace(/^\/+|\/+$/g, "");
  if (!normalized) return resolve(root);
  const parts = normalized.split("/");
  if (parts.some(p => p === "" || p === "." || p === "..")) return null;
  const target = resolve(resolve(root), normalized);
  return isInside(rootAbs, target) ? target : null;
}
```

- 拒绝 `..`、绝对路径、空段落；
- 再 `isInsideReal`；
- 根目录本身不允许删除。

### 4.4 技能

`readSkillFile` / `writeSkillFile`：

```ts
const filePath = resolveInside(asset.path, relativePath);
if (!filePath || !(await isInsideReal(asset.path, filePath))) return null;
```

只允许覆盖已存在文件，不创建新文件。

### 4.5 会话文件

`claude/sessions.ts`：

```ts
const SESSION_ID_PATTERN = /^[A-Za-z0-9_-]+$/;
```

会话 id 会直接拼进文件路径，必须挡住 `/`、`\`、`.` 等分隔符，否则 `"../../x"` 能让读取 / 删除跑到会话目录之外。

### 4.6 终端 cwd

`terminal` handler 要求 cwd 属于已登记工作区（见第 3 节）。

### 4.7 工作流产物

产物目录由运行器根据工作区路径 + workflowId + runId 计算，不接收渲染层传入的任意路径。

## 5. 凭证与临时数据

### 5.1 工作流临时投影

`claude/prepare.ts`：

```
<runtimeDir>/claude-home/.credentials.json
```

- 从 `~/.claude/.credentials.json` 复制；
- `chmod 0600`（Windows 下基本无副作用）；
- 只在节点 attempt 期间存在；
- attempt 结束由 `runChain` 的 `finally` 删除；
- 应用启动时 `purgeStaleWorkflowRuntimes()` 无条件删除 `userData/workflow-runs` 下的全部残留。

**为什么无条件删**：单实例启动瞬间不可能有活跃节点；这些目录里可能有凭证副本，尽早清掉比按时间保留更安全。

### 5.2 运行报告脱敏

`execution-report.ts`：

```ts
const SECRET_KEY = /(token|secret|password|passwd|auth|api[-_]?key|access[-_]?key|credential)/i;
```

命中的环境变量值写成 `（已隐藏，长度 N）`，不写原文。

`claude/index.ts` 的 `describeRuntimeConfig` 也对 `ANTHROPIC_*` / `CLAUDE_*` / `MCP_*` 中敏感键做同样处理。

### 5.3 MCP 密钥

- `env` / `headers` 支持 `${VAR}` 占位符；
- 字面量才标「含密钥」；
- UI 只展示标记，不额外复制到 Nova 私有库；
- 运行时写入临时 `mcp.json`，节点结束删除。

### 5.4 设置文件写入

`writeFileAtomicSync` / `writeFileAtomic`：

- 同目录临时文件 + rename；
- 进程崩溃不会留下半截 JSON；
- 失败清理临时文件。

## 6. 数据存放与隔离

| 数据 | 位置 | 说明 |
|---|---|---|
| Nova 数据库 | `~/.novastudio/data.db` | 会话、消息、员工、工作流、运行、设置 |
| 知识库 | `~/.novastudio/knowledge` | Markdown 明文 |
| 旧版归档 | `~/.novastudio/legacy-assets` | 迁移后的旧数据 |
| 工作流产物 | `<workspace>/.novastudio/workflows` | 用户工作区内 |
| 临时投影 | `<userData>/workflow-runs` | 结束即删 |
| MCP | `~/.claude.json` | 与 Claude 共用 |
| Skill | `~/.claude/skills` | 与 Claude 共用 |
| Claude 配置 | `~/.claude/settings.json` | 与 Claude 共用 |
| Claude 会话 | `~/.claude/projects/<cwd>/<uuid>.jsonl` | 与 Claude 共用 |

### 6.1 工作区隔离

- 每个工作流运行独立产物目录：`.novastudio/workflows/<workflowId>/<runId>`；
- `.novastudio/.gitignore` 内容为 `*`，不污染业务仓库；
- 不同工作流 / 运行互不覆盖；
- 删除工作区只清理 Nova 生成内容，**用户目录本身不删**。

### 6.2 会话隔离

- 工作流节点使用独立 `CLAUDE_CONFIG_DIR`；
- 普通会话用用户默认 `~/.claude`；
- 工作流会话 `source='workflow'`，不出现在普通会话列表；
- 删除会话先中断、等待收尾、删 CLI 数据、再删 DB。

## 7. 删除与级联

必须成套清理，不能留下孤儿：

- **删除项目 / 工作区**：
  1. 检查活跃运行；
  2. 删除其下所有工作流（运行 / 节点 / 事件 / 尝试 / 会话 / 产物 / 临时配置）；
  3. 释放普通会话；
  4. 删项目行；
  5. 清理 `.novastudio/workflows`；
  6. 不删用户目录。
- **删除工作流**：运行记录 + 会话 + 产物 + 临时配置 + 绑定 + 主表。
- **删除运行**：运行中禁止；删除事件 / 节点 / 尝试 / 主记录 + 会话 + 磁盘。
- **删除会话**：先 `releaseSession`，再删 DB 行（messages 外键级联）。
- **删除员工 / 知识库**：被引用时拒绝，避免运行时静默失效。

## 8. 应用更新安全

- `electron-updater` 只读打包生成的 `app-update.yml`；
- 发布渠道 GitHub Releases；
- 不允许降级 `allowDowngrade=false`；
- `autoDownload=false`，用户显式下载；
- 下载完成后不强制重启；
- 开发模式禁用更新；
- 代码签名关闭（当前无证书环境），因此安装包完整性依赖 GitHub 通道。

## 9. 外部输入风险与处理

| 风险 | 处理 |
|---|---|
| 渲染层传任意路径 | 主进程重新解析 + 越界校验 |
| 符号链接逃逸 | `realpath` 后再次 `isInside` |
| 会话 id 路径穿越 | `SESSION_ID_PATTERN` |
| 终端任意 cwd | 必须是已登记工作区 |
| 恶意 `~/.claude.json` | 无法解析时拒绝写入 |
| 超大文件 | 文本 2MB / 内嵌 25MB / 知识库 100MB / Skill 1MB |
| MCP JSON 超大 | 5MB 上限 |
| 进程挂起 | 超时 + `taskkill /T` |
| 孤儿 PTY | 窗口关闭 / 崩溃 / 退出统一回收 |
| 旧运行假装在跑 | 启动时标记中断 |
| 多实例互写 | 单实例锁 |

---

## 10. 不在范围内的安全能力

- 没有用户认证 / 权限系统；
- 没有磁盘加密；
- 没有网络传输加密之外的额外保护（模型请求由 Claude CLI 负责）；
- 不防御本机其他用户读取 `~/.novastudio`（依赖操作系统文件权限）；
- 不扫描 MCP / Skill 内容是否恶意（用户自行引入的资产）。

复刻时不要声称提供了这些能力。
