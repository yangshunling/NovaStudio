# 11 数字员工与能力绑定

## 1. 目的与边界

数字员工是一份可复用的「人设 + 能力」档案：

- 身份：姓名、职位、描述、头像；
- 行为：系统提示词；
- 能力：MCP、Skill、知识库的**引用**；
- 状态：启用 / 停用。

**员工不绑定 Agent**：执行平台由工作流节点决定（当前只有 Claude Code）。这样同一位员工可以在不同工作流 / 节点里使用不同的 Agent。

本层负责员工模型、CRUD、引用归一化与运行时能力解析。资产本身的内容在 12/13/14 管理。

## 2. 数据结构

文件：`src/shared/types.ts`

```ts
export interface DigitalEmployeeDraft {
  name: string;
  role: string;
  description: string;
  avatar: string | null;        // data URL
  systemPrompt: string;
  mcpServers: EmployeeMcpServer[];
  skills: EmployeeSkill[];
  knowledgeBases: EmployeeKnowledge[];
  enabled: boolean;
}

export interface DigitalEmployee extends DigitalEmployeeDraft {
  id: string;
  createdAt: number;
  updatedAt: number;
}
```

### 2.1 MCP 引用

```ts
export interface EmployeeMcpServer {
  assetId: string;   // 通常为 mcpServers 的服务名（可带 claude-global: 前缀）
  name: string;
  enabled: boolean;
  // 旧版内联字段，仅迁移兼容
  command?: string;
  args?: string;
  env?: string;
}
```

### 2.2 Skill 引用

```ts
export interface EmployeeSkill {
  assetId: string;   // ~/.claude/skills 下的目录名
  name: string;
  source?: string;   // 旧版路径，仅迁移兼容
  enabled: boolean;
}
```

### 2.3 知识库引用

```ts
export interface EmployeeKnowledge {
  assetId: string;   // knowledge:<slug>
  name: string;
  enabled: boolean;
}
```

### 2.4 只存引用

三者的内容都在各自资产层统一管理：

- MCP：`~/.claude.json`
- Skill：`~/.claude/skills`
- 知识库：`~/.novastudio/knowledge`

员工记录里只有 `assetId` + 展示名快照 + `enabled`。资产被删除时，员工绑定会失效，运行时给出 warning 并跳过。

## 3. 数据库

表：`digital_employees`

```sql
CREATE TABLE digital_employees (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT '',
  description TEXT NOT NULL DEFAULT '',
  avatar TEXT,
  system_prompt TEXT NOT NULL DEFAULT '',
  mcp_servers_json TEXT NOT NULL DEFAULT '[]',
  skills_json TEXT NOT NULL DEFAULT '[]',
  knowledge_json TEXT NOT NULL DEFAULT '[]',
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

### 3.1 读取归一化

`rowToDigitalEmployee` 调用三个 normalize 函数：

| 函数 | 行为 |
|---|---|
| `normalizeEmployeeMcpServers` | 新版 `{assetId,name,enabled}`；旧版内联 `{command,args,env}` 保留；空条目丢弃 |
| `normalizeEmployeeSkills` | 新版 `{assetId,name,enabled}`；旧版 `{source,name}` 保留 source |
| `normalizeEmployeeKnowledge` | 只接受 `assetId`；损坏项丢弃 |

**原则**：单条损坏不能导致整个员工列表打不开。

### 3.2 写入

`createDigitalEmployee` / `updateDigitalEmployee` 共用 `employeeParams`：

```ts
[
  draft.name,
  draft.role,
  draft.description,
  draft.avatar,
  draft.systemPrompt,
  JSON.stringify(draft.mcpServers),
  JSON.stringify(draft.skills),
  JSON.stringify(draft.knowledgeBases ?? []),
  draft.enabled ? 1 : 0,
]
```

### 3.3 绑定更新

`updateEmployeeBindings(id, mcpJson, skillsJson)` 只更新 MCP / Skill 引用，不改其他字段。资产层改名 / 删除时用它同步员工引用。

> 注意：知识库引用没有对应 helper，更新时走 `updateDigitalEmployee` 的完整草稿。

## 4. IPC

| 通道 | 行为 |
|---|---|
| `employees:list` | `db.listDigitalEmployees()` |
| `employees:create` | 校验名称 → `db.createDigitalEmployee` |
| `employees:update` | 校验名称 → `db.updateDigitalEmployee` |
| `employees:delete` | 检查工作流引用 → 删除 |

### 4.1 名称校验

```ts
function normalizeDraft(draft) {
  const name = draft.name.trim();
  if (!name) throw new Error("数字员工名称不能为空");
  if (name.length > 60) throw new Error("数字员工名称不能超过 60 个字符");
  return { ...draft, name };
}
```

主进程侧也校验，因为 UI 之外也可能直接调 IPC。

### 4.2 删除保护

```ts
function findWorkflowsUsingEmployee(employeeId): string[] {
  return db.listWorkflows()
    .filter(workflow => workflow.graph.nodes.some(n => n.config.employeeId === employeeId))
    .map(workflow => workflow.name);
}
```

被工作流节点引用时拒绝删除，并列出前 3 个工作流名：

```
无法删除：工作流「A、B」等 3 个正在使用该员工，请先在节点中解除绑定
```

**为什么**：否则这些节点会在下次运行时直接报“员工不存在”，属于不可感知的静默故障。

## 5. 渲染层

### 5.1 员工列表

`components/employees/EmployeesView.tsx`：

- 卡片展示头像、姓名、职位、描述；
- 展示已启用的 MCP / Skill / 知识库数量；
- 启用 / 停用开关；
- 新建 / 编辑打开 `EmployeeDrawer`。

### 5.2 员工抽屉

`EmployeeDrawer.tsx`：

- 基本信息：头像（上传 / 清除）、姓名、职位、描述；
- 系统提示词（多行）；
- 页签：MCP / Skill / 知识库；
- 保存 / 取消。

### 5.3 绑定页签

| 页签 | 组件 | 行为 |
|---|---|---|
| MCP | `employees/mcp/McpTab.tsx` | 列出所有 MCP 资产，勾选启用；展示来源、传输方式、只读、含密钥 |
| Skill | `employees/skills/SkillsTab.tsx` | 列出所有技能，勾选启用；展示校验状态 |
| 知识库 | `employees/knowledge/KnowledgeTab.tsx` | 列出所有知识库，勾选启用；展示文档数 |

`BindUi.tsx` 提供统一的绑定行样式。

### 5.4 禁用员工

`enabled=false` 的员工不能用于工作流节点；图校验会报：

```
节点「X」绑定的数字员工「Y」已停用
```

## 6. 运行时能力解析

### 6.1 MCP / Skill

`createAttemptChain`：

```ts
const capabilities = provider.manifest.capabilities;
const enabledSkills = employee.skills.filter(s => s.enabled);
const enabledMcp = employee.mcpServers.filter(s => s.enabled);

if (enabledSkills.length > 0 && !capabilities.skills) {
  warnings.push(`当前 Agent（${agentId}）不支持技能注入，本次已忽略 ${enabledSkills.length} 个技能。`);
}
if (enabledMcp.length > 0 && !capabilities.mcp) {
  warnings.push(`当前 Agent（${agentId}）不支持 MCP 注入，本次已忽略 ${enabledMcp.length} 个 MCP 服务。`);
}
```

具体注入由 provider 的 `prepareRun` 完成（Claude 见 06）。

### 6.2 知识库

```ts
const knowledge = await resolveEmployeeKnowledge(employee.knowledgeBases);
warnings.push(...knowledge.warnings);
const systemPrompt = buildSystemPrompt(employee, knowledge.promptSection);
```

`resolveEmployeeKnowledge`：

1. 过滤 `enabled`；
2. 扫描全部知识库，按 `assetId` 匹配；
3. 不存在 → warning；
4. 没有 Markdown 文档 → warning；
5. 生成目录 + 文件清单段落。

### 6.3 系统提示词结构

```ts
[
  `你是「${name}」，职位：${role}。`,
  employee.systemPrompt,
  knowledgeSection,
  "## 工作流协作约定\n...",
].filter(part => part?.trim()).join("\n\n")
```

知识库段落：

```markdown
## 知识库

以下是本员工可用的 Markdown 资料。任务涉及相关知识时，请先读取对应文件，
引用时注明来源文件名；不要修改知识库中的文件。

### <知识库名>
目录：<绝对路径>
- file1.md
- file2.md
- …（共 N 个文件，其余请直接浏览上述目录）
```

每个知识库最多列 80 个文件；超出的让 Agent 自己浏览目录。

## 7. 旧数据兼容

### 7.1 旧版内联 MCP

旧版员工也可能内联 MCP：

```ts
{ command, args, env }
```

运行时仍可直接注入：

```ts
function inlineMcpDefinition(ref) {
  if (!ref.command?.trim()) return null;
  return {
    command: ref.command.trim(),
    args: splitArgs(ref.args ?? ""),
    env: parseKeyValueLines(ref.env ?? ""),
  };
}
```

### 7.2 旧版 Skill 路径

旧版 Skill 引用可能是 `{ source: <绝对路径> }`。Claude 投影时：

- 新版 `assetId` → `~/.claude/skills/<key>`；
- 旧版 `source` → 直接用该路径；
- 不存在 → warning。
