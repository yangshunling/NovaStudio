# 11 数字员工与能力绑定

## 1. 目的与边界

数字员工是一份可复用的「人设 + 能力」档案：

- 身份：姓名、职位、描述、头像；
- 行为：系统提示词；
- 能力：MCP、Skill、知识库的**引用**；
- 状态：启用 / 停用。

**员工不绑定 Agent**：执行平台由工作流节点决定（当前只有 Claude Code）。这样同一位员工可以在不同工作流 / 节点里使用不同的 Agent。

本层负责员工模型、CRUD、引用归一化与运行时能力解析。资产本身的内容在 12/13/14 管理。

## 2. 数据结构

文件：`src/shared/types.ts`

```ts
export interface DigitalEmployeeDraft {
  name: string;
  role: string;
  description: string;
  avatar: string | null;        // data URL
  systemPrompt: string;
  mcpServers: EmployeeMcpServer[];
  skills: EmployeeSkill[];
  knowledgeBases: EmployeeKnowledge[];
  enabled: boolean;
}

export interface DigitalEmployee extends DigitalEmployeeDraft {
  id: string;
  createdAt: number;
  updatedAt: number;
}
```

### 2.1 MCP 引用

```ts
export interface EmployeeMcpServer {
  assetId: string;   // 通常为 mcpServers 的服务名（可带 claude-global: 前缀）
  name: string;
  enabled: boolean;
  // 旧版内联字段，仅迁移兼容
  command?: string;
  args?: string;
  env?: string;
}
```

### 2.2 Skill 引用

```ts
export interface EmployeeSkill {
  assetId: string;   // ~/.claude/skills 下的目录名
  name: string;
  source?: string;   // 旧版路径，仅迁移兼容
  enabled: boolean;
}
```

### 2.3 知识库引用

```ts
export interface EmployeeKnowledge {
  assetId: string;   // knowledge:<slug>
  name: string;
  enabled: boolean;
}
```

### 2.4 只存引用

三者的内容都在各自资产层统一管理：

- MCP：`~/.claude.json`
- Skill：`~/.claude/skills`
- 知识库：`~/.novastudio/knowledge`

员工记录里只有 `assetId` + 展示名快照 + `enabled`。资产被删除时，员工绑定会失效，运行时给出 warning 并跳过。

## 3. 数据库

表：`digital_employees`

```sql
CREATE TABLE digital_employees (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT '',
  description TEXT NOT NULL DEFAULT '',
  avatar TEXT,
  system_prompt TEXT NOT NULL DEFAULT '',
  mcp_servers_json TEXT NOT NULL DEFAULT '[]',
  skills_json TEXT NOT NULL DEFAULT '[]',
  knowledge_json TEXT NOT NULL DEFAULT '[]',
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

### 3.1 读取归一化

`rowToDigitalEmployee` 调用三个 normalize 函数：

| 函数 | 行为 |
|---|---|
| `normalizeEmployeeMcpServers` | 新版 `{assetId,name,enabled}`；旧版内联 `{command,args,env}` 保留；空条目丢弃 |
| `normalizeEmployeeSkills` | 新版 `{assetId,name,enabled}`；旧版 `{source,name}` 保留 source |
| `normalizeEmployeeKnowledge` | 只接受 `assetId`；损坏项丢弃 |

**原则**：单条损坏不能导致整个员工列表打不开。

### 3.2 写入

`createDigitalEmployee` / `updateDigitalEmployee` 共用 `employeeParams`：

```ts
[
  draft.name,
  draft.role,
  draft.description,
  draft.avatar,
  draft.systemPrompt,
  JSON.stringify(draft.mcpServers),
  JSON.stringify(draft.skills),
  JSON.stringify(draft.knowledgeBases ?? []),
  draft.enabled ? 1 : 0,
]
```

### 3.3 绑定更新

`updateEmployeeBindings(id, mcpJson, skillsJson)` 只更新 MCP / Skill 引用，不改其他字段。资产层改名 / 删除时用它同步员工引用。

> 注意：知识库引用没有对应 helper，更新时走 `updateDigitalEmployee` 的完整草稿。

## 4. IPC

| 通道 | 行为 |
|---|---|
| `employees:list` | `db.listDigitalEmployees()` |
| `employees:create` | 校验名称 → `db.createDigitalEmployee`（只落库） |
| `employees:update` | 校验名称 → `db.updateDigitalEmployee`（只落库，卡片启停也走这里） |
| `employees:delete` | 检查运行快照 / 工作流引用 / 会话绑定 → 删除并清理运行时目录 |

### 4.1 名称校验

```ts
function normalizeDraft(draft) {
  const name = draft.name.trim();
  if (!name) throw new Error("数字员工名称不能为空");
  if (name.length > 60) throw new Error("数字员工名称不能超过 60 个字符");
  return { ...draft, name };
}
```

主进程侧也校验，因为 UI 之外也可能直接调 IPC。

### 4.2 删除保护

```ts
function findWorkflowsUsingEmployee(employeeId): string[] {
  return db.listWorkflows()
    .filter(workflow => workflow.graph.nodes.some(n => n.config.employeeId === employeeId))
    .map(workflow => workflow.name);
}
```

被工作流节点引用时拒绝删除，并列出前 3 个工作流名：

```
无法删除：工作流「A、B、C」正在使用该员工，请先在节点中解除绑定
无法删除：工作流「A、B、C」 等 5 个正在使用该员工，请先在节点中解除绑定
```

删除前还会拦截两类运行态占用：

- 有工作流运行正在使用该员工（按运行启动时的快照判断）→ 拒绝删除；
- 有聊天会话正在运行该员工 → 拒绝删除。

聊天会话只是“绑定”了该员工、并未运行时，首次删除会返回 `EMPLOYEE_SESSION_IN_USE` 提示；UI 二次确认后带 `force: true` 重试，主进程会先清掉会话的员工绑定（保留会话与本地历史），再删除员工并清理 `runtime/<employeeId>` 与旧版遗留目录。

**为什么**：否则这些节点会在下次运行时直接报“员工不存在”，属于不可感知的静默故障。

## 5. 渲染层

### 5.1 员工列表

`components/employees/EmployeesView.tsx`：

- 卡片展示头像、姓名、职位、系统提示词摘要；
- 展示已启用的 MCP / Skill / 知识库数量；
- 启用 / 停用开关在卡片右上角，直接调用 `employees:update` 切换 `enabled`；
- 新建 / 编辑打开 `EmployeeDrawer`。

### 5.2 员工抽屉

`EmployeeDrawer.tsx`：

- 页签：基本资料 / MCP 服务 / 技能 / 知识库；
- 基本资料：头像（上传 / 清除，裁剪为 256×256 WebP）、姓名、职位、系统提示词（多行）；
- 描述字段仍保留在数据类型与数据库中，但当前抽屉不提供编辑入口；
- 启用 / 停用不在抽屉内，统一走列表卡片右上角开关；
- 保存 / 删除 / 取消。

### 5.3 绑定页签

| 页签 | 组件 | 行为 |
|---|---|---|
| MCP | `employees/mcp/McpTab.tsx` | 列出所有 MCP 资产，勾选启用；展示传输方式、配置文件路径、含密钥、校验状态 |
| Skill | `employees/skills/SkillsTab.tsx` | 列出所有技能，勾选启用；展示路径、校验状态 |
| 知识库 | `employees/knowledge/KnowledgeTab.tsx` | 列出所有知识库，勾选启用；展示文档数与简介 |

`AssetBindTab.tsx` 收敛三个页签共用的列表外壳、启用开关、添加 / 移除与失效条目区，`BindUi.tsx` 提供绑定动作与空态等小件。

### 5.4 禁用员工

`enabled=false` 的员工不能用于工作流节点；图校验会报：

```
节点「X」绑定的数字员工「Y」已停用
```

聊天侧同样拦截：`@` 列表只展示启用员工，选定停用员工或被停用时，创建会话 / 发送消息会直接报“已停用”。

## 6. 运行时能力解析

**运行时目录（聊天与工作流共用配置）**

员工记录与资产定义只有一份，聊天、工作流都从同一份数据库定义解析能力：

| 场景 | 目录布局 | 说明 |
|---|---|---|
| 工作流节点 | `~/.novastudio/runtime/<employeeId>/` | `claude-home/` 为 `CLAUDE_CONFIG_DIR`，`mcp.json` 为 `--mcp-config` |
| 聊天（未指定员工） | `~/.novastudio/runtime/<sessionId>/claude-home/` | 镜像全局 `~/.claude` 的 skills / plugins 等，写入全部全局 MCP |
| 聊天（`@` 员工） | `~/.novastudio/runtime/<sessionId>/employees/<employeeId>/claude-home/` | 只投影该员工启用的技能与 MCP，所有 home 共享会话的 `projects/` |

- 运行时目录是派生物，可随时删除重建；唯一不可再生的是 `claude-home/projects/`（`--resume` 凭据）；
- 保存员工只写数据库，不碰磁盘；下一次运行前按最新定义重新物化；
- 旧布局 `~/.novastudio/employee/<employeeId>/` 与更早的 `~/.novastudio/employee-runtime/<employeeId>/` 会在首次运行时自动迁移：整体保留 `claude-home`，旧 `skills/`、`mcp.json` 等派生物丢弃后按数据库重新生成；
- 同一员工的同步按 `employeeId` 串行排队，避免聊天与工作流并发“先删后建”同一份技能链接。

### 6.1 MCP / Skill

`createAttemptChain`：

```ts
const capabilities = provider.manifest.capabilities;
const enabledSkills = employee.skills.filter(s => s.enabled);
const enabledMcp = employee.mcpServers.filter(s => s.enabled);

if (enabledSkills.length > 0 && !capabilities.skills) {
  warnings.push(`当前 Agent（${agentId}）不支持技能注入，本次已忽略 ${enabledSkills.length} 个技能。`);
}
if (enabledMcp.length > 0 && !capabilities.mcp) {
  warnings.push(`当前 Agent（${agentId}）不支持 MCP 注入，本次已忽略 ${enabledMcp.length} 个 MCP 服务。`);
}
```

具体注入由 provider 的 `prepareRun` 完成（Claude 见 06）。

### 6.2 知识库

```ts
const knowledge = await resolveEmployeeKnowledge(employee.knowledgeBases);
warnings.push(...knowledge.warnings);
const systemPrompt = buildSystemPrompt(employee, knowledge.promptSection);
```

`resolveEmployeeKnowledge`：

1. 过滤 `enabled`；
2. 扫描全部知识库，按 `assetId` 匹配；
3. 不存在 → warning；
4. 没有任何文件 → warning；
5. 生成目录 + 文件清单段落（文件清单包含知识库内的全部文件，不再只列 Markdown）。

### 6.3 系统提示词结构

```ts
// 工作流节点：src/main/workflow/prompts.ts
[
  role ? `你是「${name}」，职位：${role}。` : `你是「${name}」。`,
  employee.systemPrompt,
  knowledgeSection,
  "## 工作流协作约定\n...",
].filter(part => part?.trim()).join("\n\n")
```

聊天使用 `composeEmployeeChatPrompt`：身份 + 更严格的“唯一对外身份”规则 + 员工系统提示词 + 知识库段落，不包含「工作流协作约定」。

知识库段落：

```markdown
## 知识库

以下是本员工可用的知识库资料文件。任务涉及相关知识时，请先读取对应文件，
引用时注明来源文件名；不要修改知识库中的文件。

### <知识库名>
目录：<绝对路径>
- file1.md
- file2.md
- …（共 N 个文件，其余请直接浏览上述目录）
```

每个知识库最多列 80 个文件；超出的让 Agent 自己浏览目录。

## 7. 旧数据兼容

### 7.1 旧版内联 MCP

旧版员工也可能内联 MCP：

```ts
{ command, args, env }
```

运行时仍可直接注入：

```ts
function inlineMcpDefinition(ref) {
  if (!ref.command?.trim()) return null;
  return {
    command: ref.command.trim(),
    args: splitArgs(ref.args ?? ""),
    env: parseKeyValueLines(ref.env ?? ""),
  };
}
```

### 7.2 旧版 Skill 路径

旧版 Skill 引用可能是 `{ source: <绝对路径> }`。Claude 投影时：

- 新版 `assetId` → `~/.claude/skills/<key>`，投影目录名用 `key`；
- 旧版 `source` 存在 → 直接用该路径，投影目录名取 `basename(source)`；不存在时回退到 `~/.claude/skills/<key>`；
- 不存在 → warning 并跳过。

投影优先创建目录链接（Windows 为 junction），跨盘 / 权限失败时才复制副本；解绑的技能在下一次同步时删除。

## 9. 复刻验收清单

- [ ] 员工不绑定 Agent。
- [ ] 三类能力只存引用，不复制内容。
- [ ] 旧版内联 MCP / 路径 Skill 仍可运行。
- [ ] 损坏的 JSON 条目被丢弃，不影响列表。
- [ ] 名称去空格、非空、≤60 字。
- [ ] 启用开关位于员工卡片右上角，抽屉内不再提供。
- [ ] 运行目录统一到 `~/.novastudio/runtime/<employeeId>/`，旧 `employee/`、`employee-runtime/` 自动迁移。
- [ ] 工作流与聊天共用同一份员工数据库配置，技能 / MCP 按需投影。
- [ ] 被工作流引用的员工不能删除；运行中 / 会话绑定按规则拦截或确认。
- [ ] 停用员工不能用于节点，也不能开始聊天会话。
- [ ] 运行前过滤 `enabled=false` 的绑定。
- [ ] 能力不支持时产生 warning，不阻断运行。
- [ ] 知识库不存在 / 没有任何文件时产生 warning，不阻断。
- [ ] 工作流提示词包含身份、人设、知识库目录清单、协作约定。
- [ ] 知识库提示词每库最多列 80 个文件。
