# 00 产品定位与功能全景

## 1. 产品定义

**Nova Studio** 是一个本地优先的桌面端 AI 工作台，把「AI 对话」「可复用数字员工」「可视化工作流」「本地知识与资产」组织成一条可运行的生产线。

一句话：

> 一个窗口，管理你的整个 AI 数字团队。

它不训练模型，也不提供云端服务。模型能力来自本机安装的 **Claude Code CLI**；Nova 负责组织上下文、资产、流程、运行记录与界面。

### 1.1 与 Claude Code CLI 的关系

| 维度 | Claude Code CLI | Nova Studio |
|---|---|---|
| 能力来源 | 模型、工具、MCP、Skill、登录 | 复用 CLI 的全部能力 |
| 交互形态 | 终端 | 桌面 GUI |
| 多项目组织 | 手动切换目录 | 工作区 / 会话绑定 |
| 角色复用 | 每次写提示词 | 数字员工固化人设与能力 |
| 多步骤流程 | 人工串联 | 工作流 DAG + 节点产物传递 |
| 资产 | CLI 配置 | 统一管理 MCP / Skill / 知识库 / 提示词 |
| 可观测性 | 终端输出 | 事件流落库、运行记录、执行现场 |

**关键原则**：Nova 不维护第二套 Claude 接入配置。登录、模型、权限、MCP、Skill 都直接复用 `~/.claude` 与 `~/.claude.json`。

## 2. 目标用户与场景

### 2.1 目标用户

- 同时维护多个项目的开发者 / 技术负责人；
- 需要把 AI 能力拆成“产品、架构、开发、测试、评审”等多个角色的团队；
- 希望把重复的 AI 流程固化成可调试流水线的人；
- 对数据本地化有要求、不希望对话与产物上云的人。

### 2.2 典型场景

1. **日常编码对话**：在某个工作区里让 Claude Code 读写代码，流式看到思考、工具调用与正文。
2. **角色化协作**：创建「需求产品工程师」「业务架构师」「程序员」「测试工程师」「代码评审员」，每个角色绑定不同的 MCP / Skill / 知识库。
3. **研发流水线**：把上述角色串成工作流，节点产物自动交给下游；关键节点加人工审核。
4. **定时任务**：每天 09:00 自动跑一次「代码巡检」工作流，或每隔 N 分钟执行一次。
5. **后台任务**：把一句自然语言指令加入任务中心，Nova 自动创建会话并执行。
6. **团队知识沉淀**：把 Markdown 资料收进知识库，员工按需读取并在结果中引用。
7. **个人工作管理**：待办清单记录日常事项，按周期一键生成周报草稿。
8. **提示词复用**：把反复使用的提示词存为资产，在会话输入框用 `#` 引用。

## 3. 功能全景

### 3.1 主视图（左侧导航）

| 分组 | 视图 | 路由值 | 职责 |
|---|---|---|---|
| 个人 | 会话管理 | `chat` | 多会话对话、图片输入、权限模式、工作区文件面板与终端标签 |
| 个人 | 待办事项 | `todos` | 个人清单、日历统计、周报生成 |
| 工程 | 工作区 | `workspaces` | 工作目录登记、文件 / Git / 终端控制台 |
| 工程 | 工作流 | `workflow` | 可视化编排、调试、运行记录 |
| 工程 | 触发器 | `triggers` | 定时规则与工作流绑定 |
| 工程 | 自动化任务 | `automation` | 自然语言后台任务的看板 |
| 工程 | 数字员工 | `employees` | 角色、人设、能力绑定 |
| 资产 | MCP | `mcp` | Claude MCP 服务的统一管理 |
| 资产 | SKILL | `skills` | Claude 全局技能的管理与编辑 |
| 资产 | 提示词 | `prompts` | 常用提示词的保存、编辑与复用 |
| 资产 | 知识库 | `knowledge` | Markdown 资料的目录、检索、注入 |
| 运行时 | Agent 配置 | `agents` | 本机 Claude 配置的查看与编辑 |

> 路由值定义在 `src/renderer/stores/chat.ts` 的 `ViewMode`。
> 视图切换由 `src/renderer/App.tsx` 完成。会话页常驻挂载；工作区页、工作流页首次进入后常驻（切换只隐藏）；其余视图按需挂载。终端标签挂在会话页中心标签栏，没有独立的「终端管理」视图。

### 3.2 会话管理

- 扁平会话列表，可直接开聊，不需要先建项目；
- 会话可独立绑定 / 切换 / 解绑工作区；
- 多会话可同时运行，事件按 `sessionId` 路由；
- 流式渲染思考过程、工具调用、正文；
- 支持粘贴、拖入或选择图片随消息发送（PNG / JPEG / WebP / GIF，发送前按长边 1568px 缩放）；
- 输入框旁可切换会话级权限模式（`default` / `auto` / `acceptEdits` / `plan` / `dontAsk` / `bypassPermissions`），从下一轮生效；
- CLI 发起工具授权时，输入框上方出现「需要授权」条，可展开入参并逐次允许 / 拒绝；等待 5 分钟自动拒绝；
- 输入框 `@` 只用于选择本轮回答的数字员工；`#` 用于引用文件 / 技能 / 提示词 / 知识库；
- Markdown / GFM 表格 / 代码高亮；
- 历史事件完整落库，重启后可回放（含工具调用）；
- 右侧工作区文件面板：文件树、Git 状态、只读预览；文件监听按当前展开目录按需建立。

### 3.3 数字员工

- 头像、姓名、职位、描述；
- 系统提示词（人设、职责、行为边界）；
- 从 MCP 资产勾选服务；
- 从 Skill 资产勾选技能；
- 从知识库勾选资料；
- 一键启用 / 停用；
- 员工只保存引用，资产内容在各自页面统一管理；
- 工作流节点引用员工，不重复填写角色信息。

### 3.4 工作流

**编排**

- 工作区 → 工作流两级管理；
- 画布拖拽、缩放、平移、自动布局、撤销/重做；
- 16px 网格吸附、对齐参考线、多选、整组拖动/删除；
- 节点类型：开始、结束、数字员工；
- 从右侧端口拖线，选中连线可删除/改连；
- 点击左侧员工快速加节点；
- DAG 分支并行（最多 3 个节点），AND 汇合。

**节点配置**

- 绑定数字员工；
- 任务详情（下发给员工的完整指令）；
- 失败策略：停止 / 跳过 / 重试（1-5 次）；
- 审核门禁：自动通过 / 人工审核；
- 人工审核可「要求修改」，复用同一会话续跑（最多 3 轮）；
- 驳回立即终止且不许续跑；审核等待 30 分钟按中断处理，可续跑。

**调试与运行**

- 画布内调试，不跳页；
- 节点实时状态：执行中 / 等待审核 / 成功 / 失败 / 跳过 / 取消；
- 顶部调试栏：进度、当前节点、耗时、错误；
- 可随时终止；
- 运行记录：状态、来源、开始/完成时间、耗时；
- 运行详情：对话 / 结果 / 产物文件 / 提示 / 执行信息；
- 失败/取消/中断可「继续运行」，从失败节点重跑下游；
- 任意节点可「从该节点重跑」。

**产物**

```
<workspace>/.novastudio/
└── workflows/<workflowId>/<runId>/
    ├── run.json
    ├── 01-需求分析/
    │   ├── execution.md      # 完整执行现场
    │   └── result.md         # Agent 返回
    └── 02-开发.try-2/        # 重试与首次尝试同级
        ├── execution.md
        └── result.md
```

- 首次尝试直接落在节点目录，重试用同级 `.try-N`，人工「要求修改」用 `.rev-N`；
- 不同工作流、不同运行互不覆盖；
- `.novastudio` 内置 `.gitignore`，不污染业务仓库。

### 3.5 技能（Skill）

- 使用 Claude 全局技能目录 `~/.claude/skills`；
- Nova 导入（目录 / 文件）直接写入该目录；
- 所有技能可编辑 / 删除；
- 导入技能目录（支持批量子目录、`SKILL.md.txt` 等）；
- 校验 frontmatter 的 `name` / `description`；
- 统计文件数、是否含脚本；
- 员工按引用绑定；运行时按员工同步到 `~/.novastudio/runtime/<employeeId>/claude-home/skills`（链接投影），不再为每次执行复制临时目录。

### 3.6 MCP

- 所有 MCP 定义统一存放在 `~/.claude.json` 顶层 `mcpServers`；
- Nova 新增 / 修改 / 删除直接写这份配置；
- 支持 stdio / HTTP / SSE；
- `env` / `headers` 支持 `${VAR}` 占位符；
- 字面量密钥标记「含密钥」；
- 支持 JSON 文本导入、JSON 文件导入；
- 员工按引用绑定；运行时在员工 / 会话的 runtime 目录生成 `mcp.json`，通过 `--mcp-config --strict-mcp-config` 加载。

### 3.7 知识库

- 文件库：`~/.novastudio/knowledge/<知识库>/`；
- 一个知识库一个目录，可直接用资源管理器管理；
- 只接受 Markdown（`.md` / `.markdown`），单文件上限 100MB；
- 支持子文件夹、多选上传、批量删除；
- 同名文件自动加序号，不覆盖；
- Markdown 预览支持 GFM 与代码高亮；
- SQLite FTS5（trigram）全文检索，支持中英文子串；
- 任一检索词少于 3 字符时降级为 LIKE；
- 可切换当前知识库 / 全部知识库；
- 超过 8MB 的文档不建索引，但仍可见、可注入；
- 员工按引用绑定；运行时把目录与文件清单写入系统提示词。

### 3.8 任务中心（自动化）

- 自然语言创建任务，绑定项目与 Agent；
- 后台轮询自动拾取、创建会话并执行；
- 看板四列：待执行 / 执行中 / 需处理（失败或手动停止）/ 已完成；
- 支持并发数、轮询间隔、单次运行超时；
- 执行详情跳转到对应会话；
- 可手动停止、重试。

### 3.9 触发器

- 三种规则：每天固定时刻、每周固定时刻、每隔 N 分钟；
- 触发器与工作流多对多绑定；
- 每 15 秒扫描一次；
- 工作区被占用时排队重试，最多 30 分钟；
- 应用重启后从“现在”重算下次触发，不补跑；
- 触发器卡片展示上次触发、下次触发、最近错误。

### 3.10 工作区 / 文件 / 终端

- 工作区 = 一个文件夹 + 名字（复用项目实体）；
- 文件树带 Git 状态标记；
- 文件只读预览：文本、Markdown、图片、PDF、二进制；
- 中间区域以标签页打开文件；
- 文件树按需监听当前展开目录，离开文件标签或目录收起即释放，变化 250ms 合并；
- 终端基于 node-pty，标签显示在会话页中心标签栏；默认同一工作区复用一个终端，也可强制新建多个；
- 切换页面不丢终端进程与输出；
- 从工作区打开终端会自动定位到该目录。

### 3.11 设置与主题

- 设置页拆分为五个面板：通用、外观、终端、自动化、关于与更新；
- 内置两套皮肤：经典·昼、经典·夜；
- Shiki 代码高亮主题随皮肤联动；
- 界面字号、聊天字号、终端字号独立可调；
- 通用面板配置默认 Agent、默认工作目录；自动化面板配置并发、轮询间隔、单次运行超时；
- 「运行时 → Agent 配置」页可编辑本机 `~/.claude/settings.json`：
  - Base URL、API Key / Auth Token / apiKeyHelper；
  - 默认模型 + Fable / Opus / Sonnet / Haiku 四个别名；
  - 权限模式 `permissions.defaultMode`；
  - 代理、超时、输出 token、云厂商接入等。

### 3.12 应用更新

- 基于 `electron-updater` + GitHub Releases；
- 主进程是唯一状态源；
- 支持检查、下载（显示进度）、重启安装；
- 开发模式不支持应用内更新。

### 3.13 待办事项与周报

- 个人清单，独立于工作区与项目；
- 标题、备注、优先级（低 / 普通 / 高）、截止日期、自定义标签；
- 按截止时间分组、日历筛选、完成统计、手动拖动排序；
- 已完成条目可单条或批量清除；
- 侧栏显示未完成数量角标，主进程在增删改后推送 `todos:changed`；
- 「生成周报」支持本周 / 上周 / 最近 7 天 / 自定义区间，以及简洁条列 / 正式周报 / 汇报口径三种文风；
- 周报走一次性文本生成，不创建会话、不写聊天历史；右侧流式预览，可停止、复制或导出 Markdown；
- 周期内没有记录时直接提示，不空跑模型。

### 3.14 提示词

- 把反复使用的提示词保存为独立资产（标题 + 正文）；
- 左侧列表、右侧编辑器，支持新建 / 编辑 / 删除 / 复制正文 / 插入会话输入框；
- 会话输入框通过 `#` → 提示词引用；
- `favorite` / `tags_json` 列仅为保留历史数据，当前界面不再提供收藏与标签入口。

## 4. 产品边界（非目标）

明确不做的事，复刻时不要自行添加：

1. **不做云端账号体系**：没有登录、没有云端同步、没有团队空间。
2. **不做模型托管**：不内置 API Key，不代理模型请求；一切走本机 Claude CLI。
3. **不做多 Agent provider 的完整实现**：架构保留 provider 抽象，但当前只实现 Claude Code；工作流节点固定使用第一个注册的 provider。
4. **不做知识库向量化 / RAG**：只用文件路径 + 系统提示词 + FTS5 检索，不做 embedding。
5. **不做工作流的任意脚本节点**：节点只执行数字员工，不执行用户自定义代码。
6. **不做多人协作 / 权限系统**：单机单用户。
7. **不修改用户业务目录**：删除工作区只清理 Nova 生成的内容。

## 5. 核心概念表

| 概念 | 定义 | 关键约束 |
|---|---|---|
| **工作区 / 项目** | 一个文件夹 + 名字，DB 里是 `projects` 表 | 工作流必须归属一个工作区；会话可选绑定 |
| **会话** | 一次连续对话，绑定一个 Agent 与可选工作区 | 同一会话同时只允许一个运行 |
| **消息** | 会话中的一条 user / assistant 记录 | 正文是 `AgentEvent[]` 的 JSON |
| **Agent** | 执行对话的 CLI，当前只有 Claude Code | 通过 provider 抽象接入 |
| **数字员工** | 可复用的人设 + 能力绑定 | 不绑定 Agent；工作流节点引用 |
| **MCP** | 模型上下文协议服务定义 | 统一存 `~/.claude.json` |
| **Skill** | Claude 技能目录 | 统一存 `~/.claude/skills` |
| **知识库** | Markdown 文档集合 | 统一存 `~/.novastudio/knowledge` |
| **工作流** | 由开始/员工/结束节点组成的 DAG | 只能在一个工作区内运行 |
| **运行（Run）** | 工作流的一次执行 | 有独立 ID、产物目录、状态 |
| **节点运行（Node Run）** | 某个节点在某次运行中的执行记录 | 有 attempt / round 两层计数 |
| **尝试（Attempt）** | 一次执行尝试 | 失败重试会开新 attempt、新会话 |
| **轮次（Round）** | 同一次尝试内的一轮调用 | 人工「要求修改」会 round+1，复用会话 |
| **产物（Artifact）** | 节点执行现场与结果 | `execution.md` + `result.md` |
| **触发器** | 定时启动工作流的规则 | 与工作流多对多 |
| **自动化任务** | 自然语言后台任务 | 复用会话基础设施 |
| **待办** | 个人清单条目 | 存 `todos` 表，与工作区无关；周报素材 |
| **周报** | 按周期整理的待办摘要 | 一次性生成，不创建会话、不落消息 |
| **提示词** | 可复用的提示词正文 | 存 `prompts` 表；会话中用 `#` 引用 |

## 6. 典型用户旅程

### 6.1 第一次使用

1. 启动 Nova，自动检测本机 Claude Code；
2. 未安装则展示一键安装（npm 全局安装）与实时日志；安装并检测通过前不展示
   URL / Key / 模型等配置；
3. 点击「会话管理」→ 新建会话；
4. 直接提问；需要读写文件时绑定工作区；
5. 看到流式思考、工具调用与正文；
6. 重启后仍能回放完整历史。

### 6.2 创建数字员工并用于工作流

1. 「工程 → 工作区」登记一个代码目录；
2. 「工程 → 数字员工」新建员工，填写人设与职责；
3. 在员工详情里勾选 MCP、Skill、知识库；
4. 「工作流」选择工作区 → 新建工作流；
5. 画布拖入「开始」、员工节点、「结束」，连线；
6. 配置节点任务详情、失败策略、审核门禁；
7. 点「调试」，观察节点状态与产物；
8. 在「运行记录」查看对话、结果、执行现场。

### 6.3 定时执行

1. 「触发器」新建规则（如每天 09:00）；
2. 在工作流卡片上绑定触发器；
3. 到点后自动启动；
4. 运行结果显示在运行记录与触发器卡片；
5. 工作区被占用时排队，超时给出错误。

## 7. 复刻时必须保留的产品行为

以下是用户可感知的“灵魂”，复刻时不能省：

1. **会话可独立于项目存在**——新会话默认不绑定工作区。
2. **事件流完整落库**——重启后工具调用与思考仍可见。
3. **工作流节点独立会话**——节点之间不共享上下文，只通过上游产物摘要传递。
4. **人工审核在节点执行后暂停**——不是执行前确认。
5. **驳回终止且禁止续跑**；审核超时是中断、可续跑。
6. **工作区级互斥**——同一工作区同时只能跑一条工作流。
7. **资产以磁盘为准**——MCP/Skill/知识库没有 Nova 私有副本。
8. **员工运行时按需重建**——聊天与工作流共用员工常驻运行时，attempt 结束只删会话文件，不残留临时配置目录。
9. **删除工作区不删业务目录**——只清理 Nova 生成内容。
10. **本地优先**——没有云端依赖。
