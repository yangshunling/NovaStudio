# 14 知识库与全文检索

## 1. 目的与边界

知识库把团队资料整理成 Agent 可复用的本地 Markdown Wiki。

设计原则：

- **磁盘目录是唯一事实来源**；
- 只收 Markdown（`.md` / `.markdown`）；
- 全文索引落在本地 SQLite FTS5；
- 运行时不做向量化 / RAG，只把目录与文件清单写进系统提示词，Agent 自己读取。

包含：

- 知识库目录与元信息；
- 知识库 / 文件夹 / 文档 CRUD；
- 上传、改名、删除；
- FTS5 trigram 检索与降级；
- 运行时提示词注入。

---

## 2. 磁盘布局

```
~/.novastudio/knowledge/
└── <slug>/
    ├── .kb.json          # 元信息：name / description / createdAt / updatedAt
    ├── 产品文档/
    │   ├── 需求.md
    │   └── 架构.md
    └── 会议记录.md
```

- `slug` 是目录名，也是知识库在磁盘上的唯一标识；
- 展示名存在 `.kb.json` 的 `name`；
- 文档可以是任意深度的子目录；
- `.kb.json` 不展示在 UI。

## 3. 数据模型

```ts
export interface KnowledgeBaseAsset {
  id: string;            // `knowledge:<slug>`

  name: string;

  totalBytes: number;

export interface KnowledgeDocument {
  name: string;
  relativePath: string;  // POSIX，相对知识库根

export interface KnowledgeDocumentContent {
  content: string;

export interface KnowledgeSearchHit {
  kbId: string;

export interface KnowledgeSearchResult {
  hits: KnowledgeSearchHit[];

```

## 4. 扫描与缓存

### 4.1 单库扫描

`scanDocuments(root)`：

- 递归读取 Markdown；
- 跳过 `.kb.json` 与隐藏文件；
- 最多 5000 个文件、深度 12；
- 返回 `{ documents, documentCount, totalBytes, latestUpdatedAt }`。

### 4.2 列表缓存

```ts
const LIST_CACHE_MS = 1000;
let listCache: { at: number; promise: Promise<KnowledgeBaseAsset[]> } | null = null;

export function listKnowledgeBases() {
  const now = Date.now();
  if (listCache && now - listCache.at < LIST_CACHE_MS) return listCache.promise;
  const promise = scanKnowledgeBases();
  listCache = { at: now, promise };
  void promise.catch(() => { if (listCache?.promise === promise) listCache = null; });
  return promise;
}
```

- 1 秒内复用；
- 失败结果不缓存；
- 新建 / 上传 / 删除后调用 `invalidateKnowledgeBaseCache()`。

### 4.3 元信息

`readMeta(dir, fallbackName, fallbackTime)`：

- 读取 `.kb.json`；
- 字段缺失 / 类型不对 → 回退目录名与目录 mtime；
- JSON 损坏 → 回退，不抛错。

## 5. 新建 / 更新 / 删除

### 5.1 名称校验

```ts
function validateName(name) {
  if (!name.trim()) return "名称不能为空";
  if (name.trim().length > 80) return "名称不能超过 80 个字符";
  if (/[\\/:*?"<>|\u0000-\u001f]/.test(name)) return "名称不能包含 \\ / : * ? \" < > | 等字符";
  return null;
}
```

### 5.2 目录名生成

```ts
function toFolderName(raw) {
  const cleaned = raw.trim()
    .replace(/[\\/:*?"<>|\u0000-\u001f]/g, "-")
    .replace(/^[.\s]+|[.\s]+$/g, "")
    .slice(0, 80);
  if (!cleaned) return `kb-${Date.now().toString(36)}`;
  if (/^(con|prn|aux|nul|com[1-9]|lpt[1-9])$/i.test(cleaned)) return `kb-${cleaned}`;
  return cleaned;
}

function uniqueFolderName(base) {
  let name = base, index = 2;
  while (existsSync(join(KNOWLEDGE_ROOT, name))) name = `${base}-${index++}`;
  return name;
}
```

- 保留中文；
- 替换 Windows 非法字符；
- 避开 Windows 保留设备名；
- 重名加 `-2`、`-3`。

### 5.3 创建

```ts
async function createKnowledgeBase(name, description) {
  // 1. 名称校验
  // 2. 同名（不区分大小写）拒绝
  // 3. mkdir ~/.novastudio/knowledge/<slug>
  // 4. 写 .kb.json（原子写）
  // 5. invalidate cache
  // 6. 返回 asset
}
```

### 5.4 更新

`updateKnowledgeBase(id, name, description)`：

- 只改 `.kb.json` 的 `name` / `description` / `updatedAt`；
- **不改目录名**：目录名是稳定引用，改名不影响员工绑定；
- 同名检查排除自身。

### 5.5 删除

```ts
async function deleteKnowledgeBase(id) {
  // 1. 定位 asset
  // 2. rm 整个目录
  // 3. db.deleteKnowledgeDocumentsByKb(id) 清理索引
  // 4. invalidate cache
}
```

**IPC 层前置检查**：有数字员工绑定该知识库时拒绝删除：

```
无法删除：数字员工「A、B」等 3 个正在使用该知识库，请先解除绑定
```

否则员工会在后续运行里“悄悄失去资料”，输出质量下降但界面无异常。

## 6. 文件夹与文档

### 6.1 文件夹

`createKnowledgeFolder(id, parentPath, name)`：

- 校验名称；
- 父路径必须在知识库内（词法 + realpath）；
- 同名文件夹拒绝或加序号（由实现决定，当前拒绝同名）；
- 不允许在根目录创建与元信息冲突的名字。

### 6.2 单层列表

`listKnowledgeDocuments(id, subPath)`：

- 只列当前层；
- 文件夹在前，文件按名称排序；
- 跳过隐藏文件与符号链接；
- 非 Markdown 文件不展示；
- `indexed = size <= 8MB`。

### 6.3 上传

`importKnowledgeFiles(id, parentPath, filePaths)`：

1. 父目录必须在知识库内；
2. 只接受 `.md` / `.markdown`；
3. 单文件 ≤ 100MB；
4. 同名自动改名：`name (2).md`、`name (3).md`；
5. 复制到目标目录；
6. 立即 `indexDocument` 写索引；
7. 返回 `uploaded` + `warnings`；
8. 至少一个成功才 `ok: true`。

**同名不覆盖**：用户资料优先，避免误覆盖。

### 6.4 删除

`deleteKnowledgeDocuments(id, paths)`：

- 支持文件与文件夹；
- 根目录本身不允许删除；
- 文件夹递归删除前先收集全部文档路径，逐个删索引；
- 删除后清缓存。

### 6.5 读取

`readKnowledgeDocument(id, relativePath)`：

- 只读 Markdown；
- 最多 2MB，超出截断；
- 行尾统一 LF；
- 返回 `truncated`。

### 6.6 写入

`writeKnowledgeDocument(id, relativePath, content)`：

- 只允许覆盖已存在的 `.md` / `.markdown`；
- 路径必须在知识库内；
- 最多 100MB；
- 原子写；
- 写后立即更新索引与缓存。

> 当前不支持在应用内新建文档（Roadmap 项），只能上传后编辑。

## 7. 全文索引

### 7.1 表

```sql
CREATE TABLE knowledge_documents (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  kb_id TEXT NOT NULL,
  relative_path TEXT NOT NULL,
  name TEXT NOT NULL,
  size INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  content TEXT NOT NULL,
  UNIQUE (kb_id, relative_path)
);

CREATE VIRTUAL TABLE knowledge_fts USING fts5(
  content,
  content='knowledge_documents',
  content_rowid='id',
  tokenize='trigram'
);
```

- external content 模式，正文只存一份；
- `trigram` 支持中文 / 英文子串匹配。

### 7.2 upsert

```ts
upsertKnowledgeDocument(input) {
  const existing = SELECT id, content WHERE kb_id, relative_path;

  transaction(() => {
    if (existing) {
      if (FTS ready) INSERT INTO knowledge_fts(knowledge_fts, rowid, content) VALUES ('delete', oldId, oldContent);
      UPDATE knowledge_documents ...;
      if (FTS ready) INSERT INTO knowledge_fts(rowid, content) VALUES (oldId, newContent);
    } else {
      INSERT INTO knowledge_documents ...;
      if (FTS ready) INSERT INTO knowledge_fts(rowid, content) VALUES (newId, content);
    }
  });
}
```

**external content 必须手动同步删除旧行**，否则 FTS 会残留旧内容。

### 7.3 删除

- 先 `('delete', rowid, content)` 从 FTS 删除；
- 再删 `knowledge_documents` 行；
- 按知识库删除时批量处理。

### 7.4 索引上限

- 文档 `size > 8MB` → `indexed=false`；
- 不写 `knowledge_documents`；
- 但仍出现在文件列表、仍可注入提示词、仍可预览。

### 7.5 磁盘同步

`syncKnowledgeIndex(kbId?)`：

1. 扫描磁盘；
2. 对每个文档：
   - 不索引 → 若索引里存在则删除；
   - size / mtime 未变 → 跳过；
   - 变化 → `indexDocument`；
3. 磁盘上已不存在的 → 删索引。

**触发时机**：

- 应用启动后台；
- 每次检索前，按知识库节流 2 秒（`SYNC_MIN_INTERVAL_MS`）。

**为什么节流**：每次输入都全量扫描代价太高；上传 / 删除已经即时更新，2 秒延迟只影响“外部编辑”的吸收。

**按知识库分别计时**：在 A 库搜索完，2 秒内切到 B 库搜索不能跳过 B 的同步。

## 8. 检索

### 8.1 查询拆分

```ts
function splitSearchTerms(query) {
  return query.trim().split(/\s+/).map(t => t.trim()).filter(Boolean);
}
```

多个词是 AND 关系。

### 8.2 FTS5 路径

条件：`knowledgeFtsReady && 每个词长度 >= 3`。

```sql
SELECT d.kb_id AS kbId, d.relative_path AS relativePath,
       snippet(knowledge_fts, 0, char(1), char(2), '…', 24) AS snippet
FROM knowledge_fts
JOIN knowledge_documents d ON d.id = knowledge_fts.rowid
WHERE knowledge_fts MATCH ?
  [AND d.kb_id = ?]
ORDER BY bm25(knowledge_fts)
LIMIT ?;
```

- `MATCH` 值是每个词加双引号、用 `AND` 连接；
- 双引号内的引号转义为 `""`；
- `snippet` 用 `\u0001` / `\u0002` 包裹高亮；
- `bm25` 排序；
- 最多 50 条。

### 8.3 LIKE 降级

条件：FTS 不可用，或任一词长度 < 3（中文两字词、单字母等）。

```sql
SELECT kb_id, relative_path, content
FROM knowledge_documents
WHERE content LIKE ? ESCAPE '\' [AND content LIKE ? ...]
  [AND kb_id = ?]
ORDER BY updated_at DESC
LIMIT ?;
```

- 每个词一个 `LIKE`，AND 关系；
- `escapeLike` 转义 `\ % _`；
- 自行截取命中片段（`buildSnippet`，半径 60）；
- `degraded=true`。

### 8.4 高亮

`snippet` 里的 `\u0001` / `\u0002` 由渲染层转换为高亮节点，避免把 HTML 注入 Markdown。

### 8.5 结果过滤

`searchKnowledge` 会过滤掉磁盘上已不存在的知识库（`byId.has(row.kbId)`），避免展示孤儿结果。

## 9. 运行时注入

`resolveEmployeeKnowledge(bindings)`：

1. 过滤 `enabled`；
2. `listKnowledgeBases()` 按 id 匹配；
3. 不存在 → warning；
4. `listKnowledgeFilesForAsset` 递归列出 Markdown；
5. 没有文档 → warning；
6. 生成 `ResolvedKnowledgeBase[]`。

### 9.1 提示词段落

```markdown
## 知识库

以下是本员工可用的 Markdown 资料。任务涉及相关知识时，请先读取对应文件，
引用时注明来源文件名；不要修改知识库中的文件。

### <知识库名>
目录：<绝对路径>
- file1.md
- file2.md
- …（共 N 个文件，其余请直接浏览上述目录）
```

- 每个知识库最多列 80 个文件（`MAX_PROMPT_FILES`）；
- 不复制文件、不做向量化；
- Agent 用文件读取工具按需读取。

### 9.2 注入位置

`buildSystemPrompt(employee, knowledge.promptSection)`：

```
你是「员工名」，职位：...
<员工系统提示词>
<知识库段落>
## 工作流协作约定
...
```
