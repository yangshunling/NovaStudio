# 16 任务中心与触发器

## 1. 目的与边界

本层覆盖两类自动化：

1. **任务中心**：用户录入自然语言指令，后台轮询自动创建会话并执行；
2. **触发器**：按时间规则自动启动工作流。

两者都复用已有基础设施：

- 任务中心复用会话 / AgentService；
- 触发器复用工作流运行器。

## 3. 调度器

文件：`src/main/automation/scheduler.ts`

### 3.1 状态

```ts
let timer = null;
let ticking = false;
const running = new Set<string>();   // 正在执行的任务 id
const stopping = new Set<string>();  // 用户已请求停止
```

状态全部收在 `createScheduler` 闭包里，不用模块级变量；生命周期由调用方 `start` / `stop` 掌握。

### 3.2 配置读取

```ts
function pollIntervalMs(): number {
  const raw = db.getSetting("automationPollIntervalSec");
  const sec = raw === null ? NaN : Number(raw);
  if (!Number.isFinite(sec) || sec < 1) return 30_000;
  return Math.max(Math.floor(sec) * 1000, 5_000); // 硬下限 5s
}

function concurrencyLimit(): number {
  const raw = db.getSetting("automationConcurrency");
  const n = raw === null ? NaN : Number(raw);
  if (!Number.isFinite(n) || n < 1) return 3;
  return Math.min(Math.floor(n), 10); // 硬上限 10
}
```

**为什么有硬下限 / 上限**：防止设置被写入异常值时把机器打爆或造成死循环。

### 3.3 轮询

```ts
function tick(): void {
  if (ticking) return;
  ticking = true;
  try {
    const slots = concurrencyLimit() - running.size;
    if (slots <= 0) return;

    // listAutomationTasks 是倒序（最新在前），最早的 pending 在末尾，故反转
    const pending = db.listAutomationTasks()
      .filter(t => t.status === "pending")
      .reverse();

    for (const task of pending.slice(0, slots)) void runTask(task);
  } finally {
    ticking = false;
  }
}
```

### 3.4 启动 / 停止

```ts
start() {
  if (timer) return;
  recoverStuckTasks();   // 先把上次进程遗留的 running 置为 failed
  const arm = () => {
    timer = setTimeout(() => {
      tick();
      if (timer) arm();
    }, pollIntervalMs());
  };
  arm();
}

stop() {
  clearTimeout(timer);
  timer = null;
  // 正在执行的任务也要中断，否则 Electron 退出后子进程变孤儿
  for (const taskId of running) {
    const task = db.getAutomationTask(taskId);
    if (task?.sessionId) agentService.abort(task.sessionId);
  }
}
```

**为什么用 `setTimeout` 递归而不是 `setInterval`**：轮询周期设置在下一周期即可生效。

### 3.5 遗留任务恢复

```ts
function recoverStuckTasks(): void {
  for (const task of db.listAutomationTasks()) {
    if (task.status !== "running") continue;
    patchTask(task.id, {
      status: "failed",
      error: "应用已退出，执行被中断",
      completedAt: Date.now(),
    });
  }
}
```

子进程随应用退出一同结束，启动瞬间不可能真的有任务在跑；不清理会永远停在「执行中」列。

## 4. 执行

### 4.1 `runTask`

```ts
async function runTask(task) {
  running.add(task.id);
  try {
    await execute(task);
  } catch (err) {
    // 任何未预期异常都必须落到 failed，绝不能把任务留在 running
    try {
      patchTask(task.id, { status: "failed", error: String(err), completedAt: Date.now() });
    } catch {
      console.warn("[automation] 任务收尾失败：", err);
    }
  } finally {
    running.delete(task.id);
    stopping.delete(task.id);
  }
}
```

**同步登记 `running`**：避免重入重复拾取。

### 4.2 `execute`

```ts
async function execute(task) {
  patchTask(task.id, { status: "running", startedAt: Date.now() });

  const project = db.getProject(task.projectId);
  if (!project) throw new Error("项目不存在");

  const cwd = agentService.resolveCwd(project.cwd, db.getSetting("defaultCwd"));

  // 创建会话（复用对话基础设施）
  const session = db.createSession(
    task.agentId,
    task.projectId,
    cwd,
    task.prompt.slice(0, 40),
  );
  patchTask(task.id, { sessionId: session.id });
  db.touchSession(session.id, { countDelta: 1 });

  const outcome = await agentService.run({ sessionId: session.id, prompt: task.prompt, cwd });
  flushEvents();

  // 用户已手动停止：状态在 stopTask 里已落库，这里不再覆写
  if (stopping.has(task.id)) return;

  if (!outcome.ok) throw new Error(outcome.error ?? "运行失败");

  // 被动中断（非用户发起）同样属于失败
  if (outcome.aborted) {
    patchTask(task.id, { status: "failed", error: "已手动停止", completedAt: Date.now() });
    return;
  }

  db.touchSession(session.id, { countDelta: 1 });
  push("agent:done", { sessionId: session.id, exitCode: outcome.exitCode, duration: outcome.duration });

  patchTask(task.id, outcome.exitCode === 0
    ? { status: "completed", completedAt: Date.now() }
    : { status: "failed", error: `退出码 ${outcome.exitCode}`, completedAt: Date.now() });
}
```

### 4.3 状态语义

| 状态 | 含义 | 会被自动拾取吗 |
|---|---|---|
| `pending` | 待执行 | 是 |
| `running` | 执行中 | 否 |
| `completed` | 成功 | 否 |
| `failed` | 失败 / 超时 / 手动停止 | 否 |

**关键约定**：任务一旦被拾取就必须离开 `running`。成功 → completed；失败 / 超时 / 启动失败 / 用户停止 → failed。failed 停留等待手动重试，不会自动无限重跑。

### 5.1 重试

```ts
handle("automation:retry", async ({ id }) => {
  const task = db.getAutomationTask(id);
  if (!task) return false;
  if (task.status === "running" || task.status === "pending") return false;

  // 清理旧会话（CLI 侧数据 + 索引行），避免重试产生孤儿会话
  if (task.sessionId) {
    await service.releaseSession(task.sessionId);
    db.deleteSession(task.sessionId);
  }

  db.updateAutomationTask(id, {
    status: "pending",
    sessionId: null,
    startedAt: null,
    completedAt: null,
    error: null,
  });

  scheduler.kick();  // 有空位立即拾取，否则等下一轮
  ...
});
```

### 5.2 停止

```ts
stopTask(taskId): boolean {
  const task = db.getAutomationTask(taskId);
  if (!task || task.status !== "running") return false;

  stopping.add(taskId);            // 先登记，防止执行结束覆写

  patchTask(taskId, { status: "failed", error: "已手动停止", completedAt: Date.now() });
```

## 8. 定时规则

文件：`src/shared/trigger-schedule.ts`

### 8.1 清洗

```ts
normalizeTriggerSchedule(raw) {
  if (raw.kind === "weekly") {
    const time = isValidTriggerTime(raw.time) ? raw.time : "09:00";
    const days = 合法 0-6 的整数;
    return { kind: "weekly", time, weekdays: days.length ? sortWeekdays(days) : [1,2,3,4,5] };
  }
  if (raw.kind === "interval") {
    const minutes = 有限数值 ? clamp(1, 1440, round(raw.minutes)) : 60;
    return { kind: "interval", minutes };
  }
  return { kind: "daily", time: 合法 ? raw.time : "09:00" };
}
```

- 损坏 / 缺字段回退「每天 09:00」；
- weekly 无有效星期回退工作日（周一到周五）；
- interval 夹在 1–1440 分钟。

### 8.2 下次触发

```ts
nextTriggerFireAt(schedule, from = Date.now()): number {
  if (interval) return from + minutes * 60_000;

  const [hour, minute] = schedule.time.split(":").map(Number);

  if (daily) {
    const today = new Date(from); today.setHours(hour, minute, 0, 0);
    if (today > from) return today;
    const tomorrow = ...; return tomorrow;
  }

  // weekly：最多看 8 天
  for (let offset = 0; offset <= 7; offset++) {
    const candidate = new Date(from); candidate.setDate(candidate.getDate() + offset);
    candidate.setHours(hour, minute, 0, 0);
    if (weekdays.includes(candidate.getDay()) && candidate > from) return candidate;
  }
  return from + 7 天; // 理论不可达
}
```

**严格晚于 `from`**：到点那一刻不会再次命中。

### 8.3 摘要

```ts
describeTriggerSchedule(schedule) {
  interval: `每隔 N 分钟` 或 `每隔 N 小时`
  daily: `每天 HH:mm`
  weekly: `每周（周一、周三）HH:mm`
}
```

- 星期展示顺序：周一在前，周日最后；
- 去重、排序。

## 9. 调度器

文件：`src/main/workflow/trigger-scheduler.ts`

### 9.1 常量

```ts
const POLL_INTERVAL_MS = 15_000;
const MAX_BUSY_RETRIES = 120; // 15s × 120 ≈ 30 分钟
```

### 9.2 状态

```ts
let timer = null;
let ticking = false;
const pending = new Map<string, { triggerId: string; attempts: number }>();
```

### 9.3 启动

```ts
start() {
  if (timer) return;

  // 重启后从「现在」重新计算，不补跑关闭期间错过的时刻
  const now = Date.now();
  for (const trigger of db.listWorkflowTriggers()) {
    const next = trigger.enabled ? nextTriggerFireAt(trigger.schedule, now) : null;
    if (next !== trigger.nextFireAt) patchRuntime(trigger, { nextFireAt: next });
  }

  const arm = () => {
    timer = setTimeout(() => {
      void tick().catch(err => console.error(...)).finally(() => { if (timer) arm(); });
    }, POLL_INTERVAL_MS);
  };
  arm();
}
```

**为什么重启不补跑**：否则开机瞬间可能突然连跑好几次。

### 9.4 扫描

```ts
async function tick() {
  if (ticking) return;
  ticking = true;
  try {
    await drain();  // 先送上一轮排队的工作流

    const now = Date.now();
    for (const trigger of db.listWorkflowTriggers()) {
      if (!trigger.enabled) continue;

      // 缺下次时间：补一个，不补跑
      if (trigger.nextFireAt === null) {
        patchRuntime(trigger, { nextFireAt: nextTriggerFireAt(trigger.schedule, now) });
        continue;
      }

      if (trigger.nextFireAt > now) continue;
      fire(trigger, now);
    }

    await drain();
  } finally {
    ticking = false;
  }
}
```

### 9.5 触发

```ts
function fire(trigger, now) {
  // 先推进时间，再启动工作流：即使启动抛错，也不会在同一分钟重复触发
  patchRuntime(trigger, {
    lastFiredAt: now,
    nextFireAt: nextTriggerFireAt(trigger.schedule, now),
  });

  for (const workflowId of db.listWorkflowIdsForTrigger(trigger.id)) {
    // 该工作流自己正在跑：本次跳过，不排队补跑
    if (deps.runner.hasActiveRunForWorkflow(workflowId)) continue;
    if (!pending.has(workflowId)) {
      pending.set(workflowId, { triggerId: trigger.id, attempts: 0 });
    }
  }
}
```

### 9.6 排队执行

```ts
async function drain() {
  if (pending.size === 0) return;

  for (const [workflowId, item] of [...pending]) {
    // 排队期间状态可能变化：触发器停用 / 解绑、工作流删除
    const trigger = db.getWorkflowTrigger(item.triggerId);
    const stillBound = trigger
      ? db.listWorkflowIdsForTrigger(item.triggerId).includes(workflowId)
      : false;
    if (!trigger?.enabled || !stillBound || !db.getWorkflow(workflowId)) {
      pending.delete(workflowId);
      continue;
    }

    try {
      await deps.runner.start(workflowId, {
        source: "trigger",
        triggerId: item.triggerId,
      });
      pending.delete(workflowId);
      const cleared = db.updateWorkflowTriggerRuntime(item.triggerId, { lastError: null });
      if (cleared) deps.emit(cleared);
    } catch (err) {
      const workspaceBusy = err instanceof WorkspaceBusyError;

      if (workspaceBusy) {
        item.attempts += 1;
        if (item.attempts < MAX_BUSY_RETRIES) continue;  // 继续排队
        // 超时放弃，写 lastError
      } else {
        // 图校验失败 / 工作流删除 / Agent 未安装 → 写 lastError
      }
      pending.delete(workflowId);
    }
  }
}
```

### 9.7 排队语义

- 工作区被占用 → 进入 `pending`，每 15 秒重试；
- 最多 120 次（约 30 分钟），超时放弃并写 `lastError`；
- 工作流自身在跑 → 直接跳过，不排队补跑；
- 排队期间触发器被停用 / 解绑 / 工作流删除 → 放弃；
- 用 `WorkspaceBusyError` 类型判断，不依赖文案。

## 13. 复刻验收清单

### 任务中心

- [ ] 轮询周期 5s 硬下限，并发 10 硬上限。
- [ ] 只拾取 `pending`，按创建时间从早到晚。
- [ ] 启动时把遗留 `running` 置为 failed。
- [ ] 任务一旦拾取必须离开 running。
- [ ] 未预期异常也落到 failed。
- [ ] 用户停止先登记 `stopping`，防止执行结束覆写。
- [ ] 重试清理旧会话，重置 pending，立即 kick。
- [ ] 运行中的任务不能删除。
- [ ] 应用退出时中断运行中的任务。

### 触发器

- [ ] 三种规则：daily / weekly / interval。
- [ ] 损坏规则回退每天 09:00；weekly 无星期回退工作日；interval 夹 1–1440。
- [ ] 下次触发严格晚于当前时间。
- [ ] 每 15 秒扫描，先 drain 再 fire 再 drain。
- [ ] 重启从“现在”重算，不补跑。
- [ ] 先推进 nextFireAt 再启动，避免同分钟重复。
- [ ] 工作区占用时排队，最多 30 分钟。
- [ ] 工作流自身在跑时跳过，不补跑。
- [ ] 排队期间触发器停用 / 解绑 / 工作流删除则放弃。
- [ ] 用 `WorkspaceBusyError` 判断，不依赖文案。
- [ ] 运行结束把错误回写触发器。
