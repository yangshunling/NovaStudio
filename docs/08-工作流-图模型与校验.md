# 08 工作流 — 图模型与校验

## 1. 目的与边界

本层定义工作流的**数据结构**与**合法性规则**，供主进程运行器与渲染进程编辑器共用。

包含：

- 节点 / 边 / 图的类型；
- 节点配置字段；
- 图校验算法；
- 拓扑排序与直接前驱计算；
- 不阻断运行但需要提示的警告。

不包含：

- 节点如何执行（见 09）；
- 审核 / 续跑 / 产物（见 10）；
- 画布交互（见 18）。

**为什么放在 shared**：编辑器需要在保存 / 调试前实时展示问题，不能只让主进程校验、用户看 toast。主进程的 runner 直接引用 `shared/workflow-graph.ts`，不再保留转发层。

## 2. 数据结构

文件：`src/shared/types.ts`

### 2.1 节点

```ts
export type WorkflowNodeType = "start" | "end" | "employee";

export type WorkflowFailureStrategy = "stop" | "skip" | "retry";
export type WorkflowReviewMode = "auto" | "manual";

export interface WorkflowNodeConfig {
  /** 绑定的数字员工 id；仅 employee 节点使用 */
  employeeId: string | null;
  /** 任务详情：节点执行时交给数字员工的完整指令 */
  taskDetail: string;
  failureStrategy: WorkflowFailureStrategy;
  /** 自动重试次数（不含首次），1-5 */
  maxRetries: number;
  /** 人工审核最多允许「要求修改」的轮数，0-3 */
  maxRevisions: number;
  reviewMode: WorkflowReviewMode;
}

export interface WorkflowNode {
  id: string;
  type: WorkflowNodeType;
  name: string;
  position: { x: number; y: number };
  config: WorkflowNodeConfig;
}
```

### 2.2 边与图

```ts
export interface WorkflowEdge {
  id: string;
  source: string;
  target: string;
}

export interface WorkflowGraph {
  nodes: WorkflowNode[];
  edges: WorkflowEdge[];
}
```

### 2.3 工作流

```ts
export interface WorkflowDraft {
  workspaceId: string;
  name: string;
  description: string;
  graph: WorkflowGraph;
}

export interface Workflow extends WorkflowDraft {
  id: string;
  createdAt: number;
  updatedAt: number;
}
```

### 2.4 节点类型语义

| 类型 | 作用 | 约束 |
|---|---|---|
| `start` | 唯一入口 | 不能有入边；必须恰好 1 个 |
| `end` | 唯一出口 | 不能有出边；必须恰好 1 个 |
| `employee` | 执行数字员工 | 必须绑定启用中的员工；必须可达且能到结束节点 |

> `start` / `end` 不创建节点运行记录；只有 `employee` 节点进入 `validated.order`。

## 3. 校验接口

```ts
export interface ValidatedGraph {
  /** 执行节点（不含 start/end），已按拓扑序排列 */
  order: WorkflowNode[];
  /** nodeId → 直接前驱 nodeId 列表（仅 employee 节点） */
  predecessors: Map<string, string[]>;
  /** 不阻断运行、但需要提示用户的问题 */
  warnings: string[];
}

export class GraphValidationError extends Error {
  readonly issues: string[];
  readonly warnings: string[];
}

export function validateGraph(
  graph: WorkflowGraph,
  employees: Map<string, DigitalEmployee>,
): ValidatedGraph;
```

**约定**：

- 校验失败直接抛 `GraphValidationError`，一次拿到全部问题；
- `issues` 是“不能运行”的错误；
- `warnings` 是“能运行但可能不符合预期”的提示。

## 4. 校验规则

按执行顺序：

### 4.1 节点 id 唯一性

```ts
for (const node of graph.nodes) {
  if (byId.has(node.id)) issues.push(`存在重复的节点 id：${node.id}`);
  else byId.set(node.id, node);
}
```

### 4.2 连线端点

```ts
if (!source || !target) issues.push(`连线 ${edge.id} 指向了不存在的节点`);
```

### 4.3 自连

```ts
if (edge.source === edge.target) issues.push(`节点「${source.name}」存在自连`);
```

### 4.4 重复连线

```ts
const pair = `${edge.source}\u0000${edge.target}`;
if (pairs.has(pair)) issues.push(`节点「${source.name}」到「${target.name}」存在重复连线`);
```

### 4.5 起止节点方向

```ts
if (target.type === "start") issues.push(`开始节点不能有入边`);
if (source.type === "end") issues.push(`结束节点不能有出边`);
```

### 4.6 起止节点数量

```ts
if (starts.length !== 1) issues.push(`工作流必须有且仅有一个开始节点（当前 N 个）`);
if (ends.length === 0) issues.push("工作流缺少结束节点");
else if (ends.length > 1) issues.push(`必须有且仅有一个结束节点（当前 N 个）`);
```

### 4.7 环检测（Kahn 拓扑排序）

```ts
const outgoing = new Map<string, string[]>();
const indegree = new Map<string, number>();
for (const node of graph.nodes) {
  outgoing.set(node.id, []);
  indegree.set(node.id, 0);
}
for (const edge of graph.edges) {
  outgoing.get(edge.source)!.push(edge.target);
  indegree.set(edge.target, indegree.get(edge.target)! + 1);
}

const queue = nodes.filter(n => indegree(n) === 0).map(n => n.id);
const sorted = [];
while (queue.length) {
  const id = queue.shift();
  sorted.push(id);
  for (const next of outgoing.get(id)) {
    indegree.set(next, indegree.get(next) - 1);
    if (indegree.get(next) === 0) queue.push(next);
  }
}
if (sorted.length !== graph.nodes.length) issues.push("工作流中存在环，无法确定执行顺序");
```

### 4.8 从开始节点可达

```ts
const reachable = collectReachable([starts[0].id], outgoing);
for (const node of graph.nodes) {
  if (!reachable.has(node.id)) issues.push(`节点「${node.name}」从开始节点不可达`);
}
for (const end of ends) {
  if (!reachable.has(end.id)) issues.push(`结束节点「${end.name}」从开始节点不可达`);
}
```

### 4.9 每个执行节点能到结束节点

反向邻接，从结束节点反向 BFS：

```ts
const incoming = new Map<string, string[]>();
for (const edge of graph.edges) incoming.get(edge.target)!.push(edge.source);
const canReachEnd = collectReachable(ends.map(e => e.id), incoming);

for (const node of executable) {
  if (ends.length > 0 && !canReachEnd.has(node.id)) {
    issues.push(`节点「${node.name}」无法到达结束节点`);
  }
}
```

### 4.10 员工绑定

```ts
const employee = node.config.employeeId
  ? employees.get(node.config.employeeId)
  : undefined;
if (!employee) issues.push(`节点「${node.name}」未绑定数字员工`);
else if (!employee.enabled) issues.push(`节点「${node.name}」绑定的数字员工「${employee.name}」已停用`);
```

### 4.11 至少一个执行节点

```ts
if (executable.length === 0) issues.push("工作流中没有可执行的数字员工节点");
```

### 4.12 失败

```ts
if (issues.length > 0) throw new GraphValidationError(issues, warnings);
```

## 5. 警告规则

这些不阻断运行，但会写入运行事件（`log` + `level=warning`）。

### 5.1 多下游 = 并行

```ts
if (outs.length > 1) {
  warnings.push(
    `节点「${node.name}」有 ${outs.length} 个下游：这些分支会并行执行，请确认它们不会同时写同一个文件。`
  );
}
```

### 5.2 多上游 = AND 汇合

```ts
if (node.type === "employee" && ins.length > 1) {
  warnings.push(
    `节点「${node.name}」有 ${ins.length} 个上游：需要全部上游完成后才会执行（AND 汇合）。`
  );
}
```

### 5.3 重试次数越界

```ts
if (node.config.failureStrategy === "retry") {
  if (!Number.isFinite(retries) || retries < 1 || retries > 5) {
    warnings.push(`节点「${node.name}」的最大重试次数 ${retries} 超出 1-5，运行时将按范围处理。`);
  }
}
```

### 5.4 修改轮数越界

```ts
if (node.config.reviewMode === "manual") {
  if (revisions < 0 || revisions > 3) {
    warnings.push(`节点「${node.name}」的最大修改轮数 ${revisions} 超出 0-3，运行时将按范围处理。`);
  }
}
```

### 5.5 空任务详情

```ts
if (!node.config.taskDetail.trim()) {
  warnings.push(`节点「${node.name}」未填写任务详情，运行时将使用默认指令。`);
}
```

## 6. 直接前驱

```ts
const predecessors = new Map<string, string[]>();
for (const node of executable) {
  const incomingEmployeeIds = graph.edges
    .filter(edge => edge.target === node.id)
    .map(edge => edge.source)
    .filter(id => byId.get(id)?.type === "employee");
  predecessors.set(node.id, incomingEmployeeIds);
}
```

**只保留 employee 前驱**：start / end 不参与运行时依赖。下游提示词只列执行节点的产物。

**注意**：`predecessors` 只用于：

1. 调度时判断“直接前驱是否都完成”；
2. 生成下游 prompt 的上游产物摘要；
3. 续跑时补齐未完成的上游。

start 节点的可达性已经由校验保证，运行时不把它当作依赖。

---

## 7. 拓扑序

`validated.order` 是 `employee` 节点按 Kahn 拓扑排序后的顺序。

用途：

- 创建 `workflow_node_runs` 的顺序；
- 产物目录编号（`01-节点名`）；
- 编辑器展示执行计划；
- 续跑时按拓扑序过滤执行集合。

**注意**：拓扑序不决定并行调度顺序；`execute()` 每轮扫描所有就绪节点，最多同时启动 3 个。

## 8. 图的运行时快照

启动运行时：

```ts
db.createWorkflowRun({
  graph: workflow.graph, // 复制进 workflow_runs.graph_json
  ...
});
```

**为什么**：运行中修改工作流不影响本次执行。续跑时使用 `run.graph`，不是当前 `workflow.graph`。

## 9. 编辑器的校验使用

渲染层在以下时机调用 `validateGraph`：

- 保存前；
- 点击调试前；
- 画布变更后（实时展示问题）。

失败时：

- 列出全部 `issues`；
- 展示 `warnings`；
- 禁用调试按钮。

**复刻要求**：校验函数必须在 shared，编辑器与主进程共用同一份规则，不能各写一套。

## 10. 示例

### 10.1 合法串行图

```
start → A → B → end
```

`order = [A, B]`，`predecessors = { A: [], B: [A] }`。

### 10.2 合法并行 + 汇合

```
        ┌→ A ─┐
start ──┤      ├→ C → end
        └→ B ─┘
```

`predecessors = { A: [], B: [], C: [A, B] }`。

- A、B 可并行；
- C 等 A、B 都成功后才启动（AND）；
- 如果 A 失败且策略 stop，B 会被中止。

### 10.3 非法图

```
start → A → B → A   （环）
```

→ `工作流中存在环，无法确定执行顺序`。

```
start → A → end
         ↑
         C（不可达）
```

→ `节点「C」从开始节点不可达`。

## 11. 测试覆盖

`tests/graph.test.ts` 覆盖：

- 合法串行图返回拓扑序与直接前驱；
- 拒绝环；
- 拒绝未绑定 / 停用的员工与不可达节点；
- 必须只有一个开始节点和一个结束节点；
- 结束节点必须有入边、开始节点不能有入边；
- 执行节点必须能到达结束节点，悬空的结束节点也会被拒绝；
- 分支不会阻断运行，但会提示并行写文件的冲突风险。
