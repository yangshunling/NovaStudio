# 22 构建、打包、发布与更新

## 1. 构建体系

| 层 | 工具 | 产物 |
|---|---|---|
| 主进程 | electron-vite / Rollup | `out/main/index.js`（ESM） |
| preload | electron-vite / Rollup | `out/preload/index.cjs`（CJS） |
| 渲染层 | Vite + React + Tailwind | `out/renderer/index.html` + assets |
| 安装包 | electron-builder | `release/NovaStudio-Setup-<version>-<arch>.exe` |

### 1.1 命令

```bash
npm run dev              # 开发（热更新）
npm run build            # 仅构建到 out/
npm run preview          # 预览构建产物
npm run typecheck        # 类型检查
npm test                 # 单测
npm run verify:skins     # 皮肤 token 校验（需先 build）
npm run package          # 构建 + 打包当前平台
npm run package:win      # 构建 + 打包 Windows
npm run package:win:publish  # 构建 + 打包 + 发布 GitHub Release
```

## 2. electron-vite 配置

```ts
export default defineConfig({
  main: {
    plugins: [externalizeDepsPlugin()],
    build: {
      rollupOptions: {
        input: { index: resolve(__dirname, "src/main/index.ts") },
        output: { format: "es" },
      },
    },
  },
  preload: {
    plugins: [externalizeDepsPlugin()],
    build: {
      rollupOptions: {
        input: { index: resolve(__dirname, "src/preload/index.ts") },
        output: { format: "cjs" },
      },
    },
  },
  renderer: {
    root: "src/renderer",
    resolve: {
      alias: {
        "@shared": resolve(__dirname, "src/shared"),
        "@renderer": resolve(__dirname, "src/renderer"),
      },
    },
    plugins: [react(), tailwindcss()],
    build: {
      // electron-vite 默认不压缩；这里显式开启，产物约为原来的三分之一
      minify: "esbuild",
      rollupOptions: {
        input: { index: resolve(__dirname, "src/renderer/index.html") },
        output: {
          // 按依赖类别拆可缓存 chunk，升级时只重新下载变化的 vendor 块
          manualChunks(id) {
            if (!id.includes("node_modules")) return undefined;
            if (id.includes("@assistant-ui")) return "assistant-ui";
            if (id.includes("react-markdown") || id.includes("remark-") || id.includes("rehype-")) return "markdown";
            if (id.includes("/react/") || id.includes("/react-dom/")) return "react";
            if (id.includes("shiki")) return "shiki";
            if (id.includes("@xterm")) return "xterm";
            if (id.includes("lucide-react")) return "icons";
            if (id.includes("zustand")) return "state";
            return "vendor";
          },
        },
      },
    },
  },
});
```

### 2.1 关键点

- `externalizeDepsPlugin`：better-sqlite3 / node-pty 等原生依赖不打包，运行时从 `node_modules` 加载；
- 主进程 ESM，preload CJS（sandbox 要求）；
- 渲染层 root 是 `src/renderer`；
- 别名 `@shared` / `@renderer` 只在 Vite + tsconfig 配置；
- 渲染层开启 esbuild 压缩，并按 assistant-ui / markdown / react / shiki / xterm / icons / state / vendor 拆分 chunk；
- xterm 只在打开终端标签时需要，不能混进首屏 vendor。

### 2.2 preload 路径

dev 模式输出 `index.mjs`，build 模式输出 `index.cjs`。`resolvePreloadPath()` 按 `index.mjs → index.cjs → index.js` 查找。

## 3. electron-builder 配置

`package.json` 的 `build` 字段：

```json
{
  "appId": "com.nova.app",
  "productName": "NovaStudio",
  "directories": { "output": "release" },
  "files": ["out/**/*", "package.json"],
  "extraResources": [{ "from": "resources", "to": "resources" }],
  "publish": [{
    "provider": "github",
    "owner": "yangshunling",
    "repo": "NovaStudio",
    "releaseType": "release"
  }],
  "win": {
    "target": ["nsis"],
    "icon": "resources/logo.png",
    "signAndEditExecutable": false
  },
  "nsis": {
    "oneClick": false,
    "allowToChangeInstallationDirectory": true,
    "artifactName": "NovaStudio-Setup-${version}-${arch}.exe"
  }
}
```

### 3.1 关键点

- 只打包 `out/` 与 `package.json`，源码不进入安装包；
- `resources/`（logo / NOTICE / preview）复制到安装目录的 `<resourcesPath>/resources/`；
- 关闭代码签名（`signAndEditExecutable: false`），避免无证书环境失败；
- NSIS 非一键安装，允许选择目录；
- 发布到 GitHub Releases；
- `electron-builder` 会生成 `resources/app-update.yml`，`electron-updater` 运行时读取。

### 3.2 图标

- 窗口 / 任务栏：打包后 `<resourcesPath>/resources/logo.png`，开发时项目根 `resources/logo.png`；
  `resolveWindowIcon()` 依次尝试 `<resourcesPath>/resources/logo.png` 与 `<resourcesPath>/logo.png`，
  都找不到时回退到 exe 内嵌图标；
- 安装包图标：`resources/logo.png`，由 `scripts/patch-win-exe.cjs` 在 afterPack 阶段写入 exe。

## 4. 应用内更新

文件：`src/main/updater.ts`

### 4.1 状态机

```ts
type UpdaterPhase =
  | "idle" | "checking" | "up-to-date" | "available"
  | "downloading" | "downloaded" | "error";
```

```mermaid
stateDiagram-v2
  [*] --> idle
  idle --> checking: checkForUpdates
  checking --> up-to-date: update-not-available
  checking --> available: update-available
  available --> downloading: downloadUpdate
  downloading --> downloaded: update-downloaded
  downloaded --> [*]: quitAndInstall
  checking --> error: error
  downloading --> error: error
```

### 4.2 设计要点

- **主进程是唯一状态源**：electron-updater 事件归一成 `UpdaterState`，渲染层只订阅 `updater:changed`；
- **不自动下载**：`autoDownload=false`；
- **下载完成不强制重启**：用户决定何时安装；
- **不允许降级**：`allowDowngrade=false`；
- **开发模式禁用**：未打包没有 `app-update.yml`；
- 启动后延迟 3 秒检查，避免与首屏 / 资产扫描抢网络；
- `installUpdate` 用 `setImmediate` 延后 `quitAndInstall`，保证 IPC 应答先送达。

### 4.3 CommonJS 导入坑

```ts
import electronUpdater from "electron-updater";
const { autoUpdater } = electronUpdater;
```

**为什么**：`electron-updater` 是 CJS 包，`autoUpdater` 通过 `Object.defineProperty` getter 导出，Node 的 ESM 具名导出探测识别不到。写成 `import { autoUpdater }` 构建不报错，但打包运行时会抛 “does not provide an export named 'autoUpdater'”。

### 4.4 状态快照

```ts
interface UpdaterState {
  phase: UpdaterPhase;
  currentVersion: string;
  version: string | null;
  percent: number;
  message: string | null;
  supported: boolean; // app.isPackaged
}
```

### 4.5 IPC

| 通道 | 作用 |
|---|---|
| `updater:state` | 读取当前快照 |
| `updater:check` | 主动检查 |
| `updater:download` | 下载（仅 `available`） |
| `updater:install` | 重启安装（仅 `downloaded`） |

## 5. 发布流程

### 5.1 分支约定

- `dev`：日常开发分支。功能、修复、文档改动全部提交到这里；
- `master`：发布分支。只在发版时从 `dev` 合并，并打版本标签，日常不直接提交；
- 合并使用 `git merge --no-ff dev`，保留一个明确的版本边界提交，便于回滚与对比。

### 5.2 本地发布

1. 在 `dev` 上完成开发，确认 `npm run build`、`npm run typecheck`、`npm test`、`npm run verify:skins` 通过；
2. 在 `dev` 上修改 `package.json` 的 `version` 并更新 `CHANGELOG.md`；
3. 合并到发布分支：`git checkout master && git merge --no-ff dev`；
4. 推送两个分支：`git push origin master dev`；
5. 配置 GitHub Token（`GH_TOKEN` / `GITHUB_TOKEN`）；
6. 在 `master` 上运行 `npm run package:win:publish`；
7. electron-builder 上传安装包与 `latest.yml`，创建 GitHub Release；随后 `scripts/publish-release-notes.mjs` 把 `release-notes/release-notes-<version>.md` 写入 Release 页面。

> 建议在 GitHub 的 Settings → Branches 中保护 `master`：禁止直接 push，只允许通过 PR / 合并进入。发版标签由 `master` 的 HEAD 创建，发布前确认 `dev` 已全部合并。

### 5.3 更新发现

- 客户端 `app-update.yml` 指向 GitHub Releases；
- `autoUpdater.checkForUpdates()` 读取 `latest.yml`；
- 版本比较遵循 semver；
- 下载后校验安装包完整性（electron-updater 内置）。

### 5.4 版本约定

- `package.json` 的 `version` 是唯一版本源（当前 `0.3.0`）；
- 渲染层「关于」通过 `app:info` 读 `app.getVersion()`；
- 不要在渲染层维护第二份版本号；
- `CHANGELOG.md` 按 `MAJOR.MINOR.PATCH` 记录功能变更与升级说明。

## 6. 资源与打包注意事项

- `resources/` 包含 logo、NOTICE、preview 截图；
- `extraResources` 复制到安装目录的 `<resourcesPath>/resources/`；
- 开发模式读项目根 `resources/`；
- `out/`、`release/`、`node_modules/` 不提交 Git（见 `.gitignore`）。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 打包后 `autoUpdater` 导入报错 | 用了具名导入 | 改默认导入再解构 |
| 开发模式更新报错 | 没有 `app-update.yml` | `supported=false`，跳过 |
| preload 加载失败 | dev/build 扩展名不同 | `resolvePreloadPath` 按实际文件查找 |
| 原生模块加载失败 | 被 Rollup 打包 | `externalizeDepsPlugin` |
| 安装包无图标 | `resources/logo.png` 缺失 | 检查 extraResources 与 `[patch-win-exe]` 日志 |
| 窗口左上角图标空白 | 运行时图标路径与 extraResources 布局不一致 | 检查 `resolveWindowIcon()` 候选路径与 `<resourcesPath>/resources/logo.png` |
| 窗口白屏 | 渲染层资源路径错误 | 检查 `loadFile` / `ELECTRON_RENDERER_URL` |
| 打包后皮肤缺失 | Tailwind 未扫描 skin 目录 | 检查 `@source` / 构建产物 |
